## 1. 素材特征

- **无旁白主线**:叙事由**音乐**承载,画面是素材碎片的节奏化排列;`wordline.json` 在本型常为空或仅歌词——**BGM 时间轴是骨架**,字幕/卡点以其为参照;
- **素材碎片极多且短**(0.5–3s/个),切换频率远高于其他型(视觉节拍 1–2s);
- 常含**影视/他人素材引用**:版权四要素是硬约束——转化性(有主题有观点)、控制单部引用量、不做"N 分钟看完"式纯剧透;AI 参与须标识;
- 高对比、高运动量的素材适合卡点;静态素材卡点效果差,选材阶段就该筛掉(机械口径见 §5.8)。

## 2. 节奏策略(注册表 `music` 档)

| 参数 | 缺省值 | 说明 |
|---|---|---|
| 卡时长目标 | **0.8–2.4s** | 踩鼓点/重拍;副歌段可加密到 0.5s(**显式改,不留痕不算**,操作见 §5.5) |
| BGM | **开,时间轴骨架**,增益 -12dB(全库最高档) | ducking 只在保留人声对白处生效;无对白则 ducking 关(引擎口径:工程无 audio 轨即直给,见 §5.7) |
| 转场语法档 | 硬切为主 + 模板 `motion-info` 的 slide/circleopen 备选 | 转场**落在拍点上**(操作与验收见 §5.4);禁 0.3s 内连续双转场 |
| 视觉节拍 | 1–2s | 画面事件必须跟拍,自由发挥会散 |
| 语速 | 无旁白时 `wpm=[0,0]`(不适用) | 有解说轨时按 280–330(快节奏解说) |
| 单条时长 | 15–45s | 卡点型完播压力最大,宁短勿长 |

- **开头 1–2 个镜头必须踩在重拍上**并给最强素材(卡点型的"前 3 秒"被压缩到前 2 拍;落地 = 首卡 startMs 吸附 §5.3);
- 结构原型:`强钩子(2 拍)→ 铺垫段(主歌,渐密)→ 高潮段(副歌,最密)→ 定格收尾(1–2s)`。

## 3. 字幕与卡片要点

- 字幕:`subtitle-white`(模板 `motion-info`),只上**歌词钩子/点睛短句**(每句 ≤12 字、CPS ≤9 同全库红线);不逐句上歌词——卡点型字幕是**强调**不是**翻译**(lyricOnly 配方见 §5.6);
- 歌词字幕的进出场**对齐乐句边界**(不是字级起点),允许 ±1 帧内的吸附(帧量化纪律不变);
- 卡片:几乎不用信息卡;标题花字/角标用 artboard 单卡即可,安全区同全库;
- 结尾定格帧 + 订阅引导 1–2s,勿拖(定格用 op `freeze.set`,见 §5.7)。

## 4. 管线分支(本类型特有)

| 环节 | 做法 |
|---|---|
| S0 摄取 | 素材碎片逐条 probe;**BGM 音频单独登记**(03_创作素材/bgm.*,授权源留痕);引用素材同步登记 `01_原始素材/copyright.json`(`rs_ingest.py copyright` 校验,方案 §5.5.3) |
| S1 转写 | 无旁白可整段跳过(纯画面型);有解说轨走正常对齐;**BGM 不进转写** |
| S2 粗剪 | `dead_air`/`filler` 检测基本不适用(无连续语流);碎片取舍由 Agent 按拍点判断;**节拍检测在此挂载**(`rs_beat`,操作见 §5.1) |
| S3 组装 | 多 clip 微秒级拼接;切点卡拍**不再手摆波形**——`rs_edit beat.snap` 吸附(操作见 §5.3),脚本只做帧量化 |
| S6 音效 | 转场音效慎用(会打架 BGM);重拍处可用 impact 类 ≤2 个/15s |
| S7 字幕 | 歌词短句按乐句出手;CPS/字数红线不豁免(配方见 §5.6) |
| S10 文案 | 标题带情绪词/名场面钩子;Tag 带原作名(标注引用,谨慎引流) |

## 5. 卡点操作手册(M8 落地)

> 出处:方案 §5.5.1;`rules/editing-grammar.md` 手法 15;ADR-0047(能力描述符)/ADR-0049(降级三态)。命令路径一律 `skills/cutflow/scripts/`。

### 5.1 何时跑 rs_beat(S2)

- **挂载自动**:registry `videoTypes.混剪.capabilities` 已含 `audio.beat / audio.downbeat / audio.stem`,rs_run 的 S2 挂载器按能力描述符在 S2 自动执行**工程模式**(无参,cwd=工程根):自动选 `01_原始素材` 第一条带音轨素材写产物;产物 mtime 新于素材时 `BEATS_CACHED` 跳过重算,改了 BGM 加 `--force`。
- **手动/显式**(混剪的推荐口径——检测对象是 **BGM**,不是现场素材):

  ```bash
  python skills/cutflow/scripts/rs_beat.py detect <03_创作素材/bgm音频或视频> --out <工程根> [--downbeat] [--stems]
  ```

- 产物落 `04_粗剪决策/beats.json`;READY 档(beatnet 已部署)走推理,缺组件自动降级 `onset-energy` 能量起音——**降级必留痕,不是错误**。

### 5.2 beats.json 怎么读(消费契约)

```json
{"bpm": 120.0, "meter": 4, "beats": [0, 500, 1000, …], "downbeats": [],
 "confidence": 1.0, "engine": "onset-energy", "unit": "ms",
 "degraded": true, "degradeReason": "onset-energy", "missingComponent": "beatnet", …}
```

- **单位是毫秒**(`unit:"ms"` 显式声明)——与 IR 的 `startMs` 同坐标系直接比较(方案示例是秒,本引擎统一 ms,防两套单位混写);
- `confidence` ∈ [0,1] 必记录;降级档 `degraded:true` + `degradeReason/missingComponent` 必在(验收 1);
- 降级档无小节相位:`downbeats` 为空、"重拍"按拍点网格口径处理;`--downbeat`(madmom)可用后再升级小节级卡点;
- 消费者唯一:`rs_edit beat.snap`。**缺 beats.json 时 beat.snap 以 `BEATS_MISSING` 拒绝执行——不许凭感觉摆切点冒充卡点**(禁忌表第 7 条)。

### 5.3 rs_edit beat.snap 吸附(S3)

人话:「把这几个镜头卡在鼓点上」。每条 op 把一个 clip 的 `startMs` 吸附到最近拍点:

```json
{"op": "beat.snap", "target": "<clipId>", "after": {"windowMs": 60},
 "reason": "卡点:吸附最近拍点(60ms 窗,超窗不动)", "source": "agent"}
```

- clipId 取 `rs_edit.py context <工程根>` 视图第一列(`cf-` 内容寻址或原生 id),**禁止下标**;apply 命令形如 `rs_edit.py apply <工程根> --ops ops.json --base-rev 42`(42 即视图头部 rev,以实取值替换);
- **吸附窗 60ms 硬性**:≤60ms 才动(并帧量化);超窗**不动 + WARN**;`after==before` 幂等短路。禁止强制吸附——吸不到就是吸不到,不制造假卡点(禁忌 7,ADR-0047);
- 实测两条纪律(参照 `tests/test_mixcut_e2e.py`):
  1. `beat.snap` 改 `startMs` 后该 clip 的 `cf-` 内容 id 随之变化——**同一批 apply 内后续 op 不要再引用已吸附的 clip**;定格等后续改动走**第二批 apply**(重取 context/rev);
  2. `beat.snap` **不级联邻段**:某卡切点提前/推后会改变它与前卡尾的搭接。把成串要卡的切点按「同向、逐段 ≤60ms」整链入批(链上每段都吸,边界保持无缝);孤立吸附后用 `rs_render` 的 IR 校验或人工检查确认无时间重叠;
- 序列示例:全片切点逐卡一条 `beat.snap` 入一份 ops(`{"baseRev":N,"ops":[…]}`)一次 apply → 验输出 `warnings` 恰含超窗样本、`applied` ≥ 落拍数。

### 5.4 转场落拍怎么验(机械口径)

- **切点为样本、beats 为网格**:切点 = IR 主轨各卡 `startMs`(首卡除外);对齐 = 距最近拍点 ≤60ms(与吸附窗同容差族);
- **抽查 ≥8/10**:副歌段切点优先抽样,不足 10 个再按等步长补齐全片切点;对齐数 ≥8 判过(方案 §5.5.1 验收 2);
- **无 0.3s 内连续双转场**:排序后相邻切点间距 ≥300ms(机械查 IR,验收 3);
- 转场语法:`transition` 硬切为主;落拍的本质是**切点在拍点上**,不是给每个切点加花式转场。

### 5.5 副歌加密怎么显式操作

- 副歌段(按 beats/downbeats 定段)卡时长可加密到 **0.5s**;`music` 档 `cardMs=[800,2400]` 的例外**必须留痕**,不留痕不算:
  - 选材/粗剪决策落 `04_粗剪决策/selection.json`(`climaxExplicitDense:true` + 副歌区间 + why);
  - 或走 `rs_intent` 编译/决策说明书留痕。机械判定:任何 <800ms 的卡必须落在声明的副歌区间内(验收 5 前置,参照实现同上)。

### 5.6 字幕 lyricOnly 怎么配

- wordline **只放点睛短句/歌词钩子**(本型无逐句转写):每句 ≤12 字,手写句级时间即可,进出场落在乐句边界(2 拍=1000ms 的网格点,±60ms 内);
- 生成:`rs_subtitle.py --from-wordline 05_时间线工程/wordline.json --platform douyin --max-chars 12 --out 06_成片输出`(douyin/mixcut-douyin 口径 maxChars=12、CPS≤9);字间时间戳连续,勿留停顿伪影(会被 DP 拆卡);
- **不逐句上歌词**:全片卡数 ≤ 时长秒数/2(点睛密度红线);CPS/字数不豁免;
- 样例:见 `tests/test_mixcut_e2e.py` 的 `HOOK_PHRASES`(4 句钩子对齐 2 拍乐句)。

### 5.7 BGM 增益与结尾定格

- BGM 增益 **−12dB**(music 档,全库最高)是风格包/节奏档真相源:`rs_intent --bgm auto` 选曲(库内)或用户自备曲;IR 校验 `bgm.gainDb == -12`,用户显式改值须留痕(验收 4);
- **无对白则 ducking 关**:工程无 audio 人声轨时渲染端自动直给 BGM,不要再手挂空人声;
- 结尾定格:op `freeze.set`(target=末卡,`after:{"freezeMs":1500}`)——`freezeMs` = 定格起点,静置尾 = `durationMs − freezeMs` ∈ 1–2s(验收 8);定格在第二批 apply(见 §5.3 纪律 1)。

### 5.8 选材筛静态(机械口径)

- 纯色/无运动素材卡点效果差,S0 后即筛:逐条登记 keep/drop 与理由(`selection.json` 的 `dropped[].reason` 以 `static:` 开头);IR 卡数 = keep 数,静态素材不得进素材带/keep 区间。

## 6. 该型验收清单(M8 起逐条机械判定;L1 目测 + 用户 L2 对照项单独标注)

- [ ] **1 beats.json 存在且 confidence 已记录**(降级时 degraded=true + degradeReason/missingComponent)——查 `04_粗剪决策/beats.json`;
- [ ] **2 卡点成立**:切点样本对拍点网格,±60ms 内 ≥8/10(副歌段优先)——beats.json + IR 切点比对(§5.4);
- [ ] **3 无 0.3s 内连续双转场**——相邻切点间距 ≥300ms(IR 机械查);
- [ ] **4 BGM 增益 = −12dB 或用户显式改值(留痕)**——查 IR.bgm.gainDb / intent_decisions;
- [ ] **5 字幕仅点睛短句**:每卡 ≤12 字、CPS ≤9、密度 ≤1 卡/2s;sub-800ms 卡必须在留痕的副歌区间——查 ASS + selection;
- [ ] **6 版权**:素材引用合规(转化性、单部引用量克制、无纯剧透替代),`copyright.json` 登记过(`rs_ingest.py copyright` → COPYRIGHT_OK),**交付说明书.md 必含「版权与 AI 标识」节**;
- [ ] **7 AI 生成/参与已标识**——`copyright.json.aiDisclosure=true` + 说明书 AI 标识确认项;
- [ ] **8 结尾定格 + 引导不拖沓;全片 ≤45s**(超长需用户显式确认)——末卡 freezeMs ≥1s、静置尾 1–2s、IR 总长 ≤45s;
- [ ] (L1 目测)重拍处画面确有切换的**观感**成立;无半帧闪烁;BGM 与画面气质匹配——机械口径过闸后仍由用户 L2 终验。
