# videoType = `screen-recording` · 录屏教程(正式册)

> M6 预登记册 → M8 第二波正式扩册(方案 §5.5.4 + §5.9 手法 25)。来源分级:【官方】Bilibili 创作学院教程类规范;【经验】录屏教学从业者共识;【内部】CutFlow 机械口径。风格包:`screen-tutorial`(templates/styles/packs/screen-tutorial/,slow 档 + `tutorial-clean` 字幕)。

## 1. 素材特征(与口播教程的根本差异)

- **画面即内容**:录屏本体是信息主线,解说只是导航;S1 转写覆盖的是解说词与系统语音;
- **大量等待/输入/停顿废段**:渲染、加载、安装、转圈——占时长但不占信息,是本类型粗剪的主要裁剪对象(§3);
- **信息密度高但视觉变化少**:观众注意力需要人工制造的节拍(缩放/高亮/章节卡)来引导;
- **鼠标与键盘是注意力焦点**:点击必须落拍(§4),光标高亮不得遮挡操作区(§5);
- **文字清晰度是死刑线**:低于 1080p 的录屏放大即糊,S0 就该拦截,不许硬拉;
- **敏感信息高发**:地址栏、终端、配置文件里全是密钥/内网地址,交付前必须打码(§6)。

## 2. 新增能力与命令路径(M8)

| 能力 | 命令 | 产物 | 降级档 |
|---|---|---|---|
| 等待段分析 | `python skills/cutflow/scripts/rs_screen.py analyze 01_原始素材/a.mp4 --cursor --zoom --keys --redact --waiting --out <工程根>` | `04_粗剪决策/screen.json`(`waiting[]/waitingTotalMs/cursorTrace/clickPoints/zoomPlan/keyHints/redactBoxes`) | waiting 恒可用(ffmpeg+标准库);光标/点击/打码缺 opencv 时降级留痕(`degradedSections`) |

## 3. 等待段压缩规则(方案 §5.9 手法 25)

- **判据**:≥ **2.0s** 无视觉变化(降采样灰度帧平均绝对差)**且**无语音(-35dB silencedetect)→ `reason=waiting` 刀;
- **处置**:**加速 2–8× 或删除**。当前 cutlist 管线机械执行的是「删除」(remove 过 guard 后进 keep 重算);加速属下游变速(S3 后 rs_edit 变速 op / 渲染端),砍不动的长等待(>30s)建议人工改加速并留 note;
- **防误删(硬规则)**:waiting 区间内出现**任何一个转写字**(ASR 有人声)即整段放弃——「画面静止但解说不停」是教程常态,帧差静止 ≠ 可删;screen.json 的静音判据是第一道闸,rs_cut 的字重叠过滤是第二道;
- **guard 档位**:`waiting` 只硬要求 `wordClipped`(不切断字内音素)+ `tailKeep`(后留 ≥60ms);inSilence/outSilence 天然满足降为告警项(rules/roughcut.md §5);
- 检出率预期:教程类素材等待占比 30–60% 属正常;检出 0 段先查 `screen.json` 是否存在、素材是否真有静止段。

## 4. 点击落拍(±80ms)

- **判据**:点击瞬间(rs_screen `clickPoints[]`)→ 缩放动作(`zoomPlan[]`)在 **±80ms** 内启动;`zoomPlan` 与 `clickPoints` 同源同毫秒生成,延迟恒为 0,机检断言即「zoomPlan 覆盖全部 clickPoints」;
- 缺 opencv 降级为 `static-zoom`(固定居中 punch-in),点击落拍失效 → L1:人工在时间线上补 punch-in;
- 点击点判据(READY 档):光标滞留 ≥400ms 后快速移动;缩放倍率 1.4(punch-in,与手法 18 同值)。

## 5. 光标高亮:可见但不遮挡

- 高亮圈跟随光标轨迹(cursorTrace),圆心即点击点;**圈外沿不得压住被讲解的 UI 元素**(按钮/菜单/输入框)——高亮是「指」,不是「盖」;
- punch-in 放大的是点击点邻域,1.4× 下 UI 上下文仍在画面内,不因缩放丢失操作区参照;
- 机检:高亮圈 bbox 与讲解 UI 元素 bbox 求交 = 空;圈是否真「可见」(对比度/直径)是 L1 目测。

## 6. 章节卡必须

- **每个逻辑段一张章节卡**(artboard `section` 模板),步骤编号连续不跳号;风格包已声明 `opener:1 / section:N / endcard:1`(templates/styles/packs/screen-tutorial/params.yaml `artboard.templates`);
- 键位/快捷键讲解配 `screen.keys` 提示卡(缺 opencv 降级:无检测,人工补 artboard 卡);
- 卡片视觉借 artboard `data-longform`(报告型步骤语言),与操作分段同构。

## 7. 敏感信息打码

- `rs_screen analyze --redact` → `redactBoxes[]`(梯度形态学类文本候选区,**机检只圈候选不判定内容**);
- **打码落地**:候选区确认敏感后由渲染端做遮挡(或回录屏工具裁剪重出),`--redact` 至少保证候选留痕;机检漏检率不为零 → **L0 抽帧 + L1 目测是交付前置**,`tiers.redact.note` 即该提醒;
- 降级档(无 opencv):`redactBoxes=[]` + L1 提醒,交付前必须人工过一遍。

## 9. 管线分支(本类型特有)

| 环节 | 做法 |
|---|---|
| S0 摄取 | 录屏分辨率 ≥1080p 硬校验;多段录屏逐条 probe(`rs_ingest.py scan <工程根>`) |
| S1 转写 | 解说词热词表前置(软件专名/菜单名);onnx 降级同全库纪律 |
| S2 录屏分析 | `rs_screen.py analyze --cursor --zoom --keys --redact --waiting`(挂载器工程模式无参全量) |
| S2 粗剪 | `rs_cut.py --detect waiting`(或 `all,waiting`);操作步骤链不得断号——等待段可删,**操作本身不可删** |

## 10. 该型验收清单(方案 §5.5.4 七条,附机械检查路径)

- [ ] **等待/输入废段已压缩,总时长较源减少 ≥30%**——机检:`rs_cut --detect waiting` → `--apply` → 渲染后 ffprobe 成片时长,`(源 − 成片)/源 ≥ 0.30`;fixture 已知等待占比时可精确核对 removedMs;
- [ ] **每次点击有视觉反馈;点击与视觉反馈延迟 ≤80ms**——机检:`screen.json` 中 `zoomPlan` 覆盖全部 `clickPoints`(同源延迟 0);fixture 已知点击时刻时,`|clickPoints.tMs − 注入高亮时刻| ≤ 80`;
- [ ] **光标高亮可见但不遮挡被讲解的 UI 元素**——半机检:高亮圈 bbox × UI 元素 bbox 求交 = 空(几何可断言);「可见性」L1 目测;
- [ ] **章节卡齐全(每个逻辑段一张)**——机制机检:风格包 `artboard.templates` 含 `section:N` 且 N ≥ 逻辑段数;逐卡目测 L1;
- [ ] **密钥/隐私信息已打码**——机检:`redactBoxes` 非空且覆盖注入的已知敏感区;最终是否敏感 L1 目测(`tiers.redact.note` 提醒必须在);
- [ ] **字幕每卡合规;CPS ≤9**——机检:`rs_verify.py`(check_subtitles 按 maxChars/CPS 硬判)+ `cards.json` 逐卡字数 ≤ 平台上限(16:9 为 22);
- [ ] **画中画人脸(若有)未遮挡关键 UI**——素材无画中画时该条豁免(留痕"N/A");有画中画时 PiP bbox × 关键 UI bbox 求交 = 空(几何可断言),遮挡判定 L1。

> L1 条目不是"不查",而是"机器给证据、人做结论"——证据(圈选框/警告 note/几何数据)必须落在产物 JSON 里留痕。
