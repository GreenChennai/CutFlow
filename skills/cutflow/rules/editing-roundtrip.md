# Editing Roundtrip — 双向编辑闭环与剪映单向出口(ADR-0052)

> 一句话:**能回环的只有 CutForge 主通道;剪映是单向出口,只进不回。**
> `成品/` 是只读交付区(不可编辑产物),可编辑的半成品全部留在工程区。

## 产物三分(ADR-0052)

| 类 | 定义 | 落点 | 回环 |
|---|---|---|---|
| 工程 | S0–S11 全部中间产物 + 母版 | 工程区阶段目录 | ✅(rebuild.py + 阶段缓存) |
| 半成品 | 可继续编辑且编辑可被 Agent 感知 | 工程区内(**不进 `成品/`**) | ✅ 双向(CutForge 主通道) |
| 成品 | 最终合成/最终导出 | `成品/`(只读语义) | ❌ 不需要 |

发布用 `rs_ingest.py deliverables <工程根> --publish`:拷贝/衍生到 `成品/` + §4.3 真对账;
旧 `成品/` 先备份到 `_内部状态/backup/publish-<时间戳>/`;工程文件/剪映草稿混进
`成品/` 会被只读区断言拒绝(`READONLY_ZONE_VIOLATED`)。

## CutForge 主通道(双向闭环,四步)

人改盘面 → 标脏 → 看人话差异 → 定向重建:

1. **人改盘面**:在 CutForge 编辑器里改(工程文件 `05_时间线工程/project.json`
   是同源唯一真相源,不存在第二份副本);
2. **标脏**:`rs_run.py --status --root <工程根>` 读 `.cutforge/session-summary.json`
   识别外部编辑,受影响阶段转 stale(脏账可见,而不是假装全绿);
3. **人话差异**:`rs_editor.py diff <工程根>` 把人改的内容翻成可读摘要
   (session-summary 优先,否则与 bases/ 基线对比),确认改动范围;
4. **定向重建 + 复检**:`rs_run.py --root <工程根> --from S3 --force` 只重跑受影响段,
   再 `rs_verify.py <工程根>` 过 L0(阶段缓存让"改一处"不等于"整片重来")。

闭环成立的关键:**编辑必须落在内容寻址锚点上**(时间轴/字级/卡片 id),盘面改动才
能被机械感知。这是剪映给不了的(见下)。

## 剪映单向出口(诚实说明)

`rs_jy_draft.py` 保留「IR → 5.9 明文草稿」导出能力,草稿落在工程区
`05_时间线工程/导出/剪映59/`(半成品出口,不是交付物、**不进 `成品/`**)。
用户可在剪映里精修,但**不要期待改动回流工程区**;剪映侧成品请在剪映里直接导出。

### 为什么不做回环

1. **规范化重排**:5.9 明文草稿(draft_content.json)虽可解析,但剪映打开/保存时会
   对草稿做内部规范化重排(轨道顺序、字段补全、素材引用重写),盘上字节与语义都
   不再是写出的原样;
2. **元素 id 不稳定**:剪映为片段/素材重新分配内部 id,我们没有可靠办法把"剪映改过的
   那一刀"映射回 IR 的 clip/wordline 锚点;
3. **锚点不可信**:内容寻址锚点要求"同内容必得同地址"。以上两条导致无法建立**可信**
   的锚点映射——回环 diff 会同时包含真实改动与重排噪声,宁可不做;
4. **6.0+ 加密**:剪映 11.3/6.0+ 草稿加密,永不读写(铁律,见 rules/jianying.md)。

结论:追求剪映双向回环被 ADR-0052 **明确否决**(技术成本高、不可靠);需要"改了让
Agent 接住"的编辑,一律走 CutForge 主通道。

### 半成品入口(给用户的一页纸)

`成品/半成品入口.md` 由 publish 生成,写明:可编辑工程在哪(工程文件与剪映草稿落点)、
「改完怎么让 Agent 接住」两步(标脏 → 定向重建重发布)。它是指针文件,不复制工程。

## 门禁

- 只读区:`tests/test_deliverables.py` —— `成品/` 出现 project/wordline/cutlist/notes、
  `*.draft_content.json`、rebuild.py 必红;`--publish` 幂等;缺项非零退出;
  `rs_cleanup` 永不触碰 `成品/`;半成品入口指向的路径必须存在。
- 草稿落点:草稿写盘只经 `rs_paths.jianying_draft`(路径唯一真相源)。
