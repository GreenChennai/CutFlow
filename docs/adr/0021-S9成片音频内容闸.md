# ADR-0021:S9 新增成片音频内容闸(ASR 对账)

状态:已采纳 ｜ 日期:2026-09-13(v0.8.2,BUGREPORT-20260913 B10)

## 背景

纯口播复测中,首版成片的**音频内容损坏**(粗剪后每段人声从源 0s 取,B1):片头问句反复出现、全程音画错位。但所有既有闸——L0 六项、`rs_sync` 全绿、总时长对账——全部通过。原因:所有检查只对账 ass↔wordline 与**时长**,没有任何检查验证**成片音轨的内容**。这是验证体系的结构性盲区:时长正常 ≠ 内容正确。

## 决策

1. **S9 增加音频内容闸**:`rs_sync --video 成片.mp4 --audio-content`。对成片音轨抽 16k wav → 自带 ASR(`tools/fun_asr.py`)→ 与 wordline 文本归一对比,三条判据:
   - **片头句出现次数 = 1**(≥2 即 B1 式"每段重播片头"特征,wordline 首句归一后在 ASR 文本中计数);
   - **归一相似度 ≥ 0.90**(去标点/空白/大小写,`difflib.SequenceMatcher`;实测正常 ≈0.98,AAC 重编码噪声留余量);
   - **无重复段**(12 字 n-gram 出现 ≥3 次)。
2. **成本可接受**:wordline 已是文本真相源,ASR 本就是管线自有能力;结果按「成片 hash + wordline hash」缓存于 `06_output/audio_check.json`,增量重跑零成本。
3. **失败语义**:跑出问题 → `rs_sync` 硬失败(exit 4,进 sync_report);**工具/素材不可用 → skipped**,不硬失败(缺 ASR 环境是工具缺口,不是内容损坏;闸的缺席必须显式留痕)。
4. S9 的注册命令(`rs_run.spec()`)固定带上 `--video {final_video} --audio-content`,取最新 `final_*.mp4`。

## 后果

- B1 级"时长正常但内容损坏"从此有机械闸;交付前的最后盲区关闭;
- 每次 S9 首跑多一次 ASR 成本(缓存后摊平);ASR 不可用的环境该闸静默缺席——`sync_report.md` 会显式写"跳过"与原因,Agent 交付时应核对;
- 相似度阈值 0.90 是经验值(ASR 对 TTS/AAC 噪声的听写差异);误报时优先人工听样本,不建议放宽阈值。
