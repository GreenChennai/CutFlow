# ADR-0040: 提示词入口采用"意图编译器 + 风格注册表",不把语义塞进 SKILL 文案

日期: 2026-09-20 · 状态: 已采纳(2026-09-20 迭代落地) · 关联: ADR-0018(videoType 取代 genres)、ADR-0034(五份 schema 为唯一契约真相源)、ADR-0037(N 后端注册表)

## 背景

"给提示词就全自动出片"要求 Agent 面对任意自然语言提示词都能稳定落到管线上。若靠 SKILL 文案引导 Agent 临场发挥(自行推断节奏、字幕样式、卡片模板),结果是:不可复现(同提示词两次跑法不同)、不可对拍(没有中间产物可检查)、费 token(每次重新推理一遍本可查表的默认值);且"任何风格"需要长期可扩展,写死在文案或代码分支里都走不远。

## 决策

1. **新增意图编译器**:prompt → `brief + plan` 走确定性编译——校验必填与枚举 → 补默认 → 查风格注册表 → 落现有 intake 产物。Agent 只保留两处语义工作:「读懂提示词 → 写 brief.json + plan.json」与「写文案」;其余一律查表。
2. **新增风格注册表**:`videoType × 平台预设 × 节奏档 × 字幕样式 × 卡片模板 × BGM 库 × 转场语法` 的组合以数据条目声明,编译时查表,不在代码里写风格分支。
3. **`videoType` 视为开放注册表,可继续增补新类型**(2026-09-20 用户确认):现有 5 型(纯口播 / 口播+动画 / 纯动画 / vlog / 混剪)+ 预留扩展位(screen-recording / interview / drama / film-commentary);新类型 = 新增一册 video-types + 一条注册表条目,不改引擎。
4. **推断必须留痕**:一切默认推断显式标 `inferred=true` 与来源(registry/default),与"用户明说"区分;全量决策随工程落盘并并入 pipeline.json 的 `decision_log`,`decision_log` 是交付物的一部分。

## 取舍

- 付出:多维护"编译器 + 注册表"一层(注册表条目、videoTypes 分册、决策留痕格式)。
- 换来:同输入字节级同输出(可复现)、推断表可人工复核(可解释)、新风格不改引擎(可扩展)、查表替代临场推理(省 token)。

## 被否决的替代

- **只写 SKILL 文案引导临场发挥**:否决——不可复现、不可对拍,且文案越写越胖(SKILL 有 270 行硬约束)。
- **把风格写进代码分支**:否决——每加一种风格都要改引擎代码,与"可增加其他类型"的确认相悖。
- **限定固定类型集合不再扩**:否决——与用户"videoType 可继续新增类型"的确认直接相悖。

## 后果

- 新风格落地路径固定:注册表条目 +(必要时)一册 video-types,引擎零改动;videoType 三处口径(CONTEXT / SKILL / 注册表)必须同步,由能力目录对拍门禁兜底。
- `decision_log` 成为每次交付的一部分,"为什么这么剪"可事后审计。
- 意图编译器位于 S0 之前,不触碰 S0–S11 任何既有阶段语义。

## 落地证据

- `skills/cutflow/scripts/rs_intent.py`:`compile` 子命令(提示词 → brief.json + plan.json → intake 产物;纯函数式——产物与 intent_decisions.json 不含时间戳,同输入字节级一致,由 `tests/test_v21_prompt_auto.py` 断言)。
- `skills/cutflow/templates/styles/registry.json`:风格注册表(videoTypes 5 型、pacingTiers 4 档、entries 7 条,含 vlog-douyin / mixcut-douyin)。
- videoType 开放注册表扩容:`skills/cutflow/rules/video-types/` 五册(纯口播 / 口播+动画 / 纯动画 / vlog / 混剪);CONTEXT.md 的 videoType 词条已同步开放注册表口径。
- 能力目录登记:`skills/cutflow/capabilities.json` 含 rs_intent 条目;手册命令对拍门禁(`tests/check_manual_cmds.py`)覆盖其命令行。
