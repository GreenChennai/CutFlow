# ADR-0008:重型依赖走 GitHub Release 自持 + fetch 脚本;感知能力 Agent 优先、本地兜底

状态:已采纳 ｜ 日期:2026-09-08

## 背景

OCR.exe(107.8MB onefile 零外部依赖)与 VQA(qora_assets 618MB 纯 Rust 引擎免 Python)内嵌在代码路径里,仓库不带、新机器难部署。用户要求:发布到本项目 GitHub Release 供下载;OCR/VQA 作为**备选**——Agent 自身有视觉能力时优先用自身,仅在 Agent 不可用/用户明示/config 强制开关时才调本地模块(参考 artboard 做法);FFmpeg 也要一键部署脚本。

## 决策

1. **发行为**:CutFlow 仓库建 release `v0.3-dependencies`,附 `ocr-module.zip`(~113MB)与 `vqa-module.zip`(~630MB,**相对路径重打包**——artboard v1 的 zip 内嵌绝对临时路径导致解压后 probe 失败,是已知瑕疵,不得复刻);发行说明结构照 artboard:一句话定位 → 大小预期 → 一条命令部署 → 自动写 config → doctor 验收。
2. **fetch 脚本**:`tools/fetch_deps.py ocr|vqa`(蓝本 artboard fetch_model.py,改进:相对 arcname + SHA256 校验 + 自动回写 config);`tools/fetch_ffmpeg.py`(蓝本 MomentShift ffmpeg_download.py 多镜像回退:直连 GitHub → ghproxy 镜像 → gyan.dev,流式 .part + 非空校验 + 解压抽 bin)。
3. **备选策略**:`config.sense.force_local`(默认 false)。SKILL/rules 规定:Agent 自带视觉时**优先自己看图**;批量图处理、Agent 无视觉、force_local=true 三种情况才调 rs_sense(OCR.exe/VQA)。rs_sense 保留为独立可调用原语。

## 后果

- 仓库保持轻量(仓库只有脚本,重物在 Release);新机器一条命令部署;
- Release 资产流量不计入 git;VQA zip 600MB 级,上传一次永久可用;
- Agent 视觉优先省去本地推理开销;纯 API/无头环境下 force_local 兜底。
