# ADR-0050: 抠像重建与质量门禁（部分取代 ADR-0031）

日期: 2026-09-25 · 状态: 已采纳（待落地） · 关联: ADR-0031（**部分取代**）、ADR-0022／0029（历史，仍作废）、ADR-0049

## 背景

用户明确：**「之前强制关闭抠像，是因为抠像水平太差太差，为了提升剪辑效率才不得不强制关闭」**。这与 ADR-0031 的背景段完全吻合——ADR-0031 自己写的第 1 条理由就是「实拍绿幕的打光不均、投影、溢色、与幕布同色的服饰，本质是拍摄与预处理问题，算法只能补到有限程度」，第 3 条是「职责错位」。

**但结论要改写**：ADR-0031 的修法是「整条砍掉，交给用户」；本轮要的修法是「**重建，但用质量门禁把住**」——因为本轮新增的短剧／影视解说／录屏类型与「手法丰富」诉求，很大程度依赖人物分离与背景可控。

**关键约束**：ADR-0031 的技术路径（`chromakey` / `colorkey` / `despill` / killRect / 比值键控 v2 那一族）**已被证明天花板低**，重建**不复用那条路**。改用**时序引导的神经网络视频抠像**（RVM：RNN + 时序记忆，无需绿幕，4K 76FPS / HD 104FPS on GTX 1080Ti；逐帧备选 `rembg` / BRIA RMBG）。

## 决策

1. **新增 `scripts/rs_matting.py`**，能力 id `vision.matting`，走 ADR-0049 懒加载（`venv-torch`，~480MB）。
2. **S0 幕布检测改为「检测 → 分流」**（不再是无条件阻断）：

```
S0 检测到幕布
├── (a) 用户预处理（默认，ADR-0031 原行为不变）
├── (b) 启用自动抠像：需要 brief 显式允许（autoMatting: true）或用户当场指令「帮我抠像」
│       └── 走质量门禁：达标 → 进入管线；不达标 → 阻断 MATTE_QUALITY_FAIL + 给降级建议
└── (c) 用户确认误判 → rs_ingest green-ok（原行为不变）
```

**默认行为仍是 (a)**——不改变现有用户预期，也不违反 ADR-0031 的默认口径。

3. **五项质量门禁**（全部客观、可机械判定）：

| # | 指标 | 判据（建议初值，实测定档） | 为什么 |
|---|---|---|---|
| 1 | **时间一致性** | 相邻帧 alpha 的 IoU 中位数 ≥ 0.985；单帧抖动率（\|ΔIoU\| > 0.05）≤ 2% 帧 | 抠像最刺眼的问题是「边缘呼吸／闪烁」，ADR-0031 时代的 `geq` 字节域事故即此类 |
| 2 | **毛边率（halo）** | 边缘 3px 环带的「残留幕色」像素占比 ≤ 1.5% | 溢色／未去净的绿边是廉价感的来源 |
| 3 | **发丝／细结构保真** | 高频细节保留率（与原始亮度高频能量比）≥ 0.75 | ADR-0031 自认的固有歧义就在这里 |
| 4 | **半透明正确性** | alpha 直方图在 (0.05, 0.95) 有非退化分布；无「硬二值化灰边」 | 决定边缘是否「剪贴画感」 |
| 5 | **吞吐** | 1080p ≥ 12 fps（GPU）／≥ 1.5 fps（CPU-only 降分辨率档） | 剪辑效率是用户关闭抠像的直接原因，**速度是硬指标** |

4. **门禁三态**：`PASS`（启用）／`WARN`（可用但交付说明标注「边缘质量一般」，用户可显式接受）／`FAIL`（阻断，输出诊断帧与建议：改用更干净的背景、提高源分辨率、改走用户预处理）。
5. **IR 字段**：新增 `matte` 块（**不复用旧的 `chroma`/`background`**，避免与 ADR-0031 的语义混淆）：

```json
{"matte": {"engine": "rvm",
           "quality": {"verdict": "pass", "metrics": {"temporalIoU": 0.991, "haloRatio": 0.008}},
           "bg": {"src": "03_创作素材/背景/虚拟背景.png", "mode": "cover"},
           "cacheVer": 8}}
```

6. **旧字段仍报错**：`chroma` / `background` 继续被 `rs_ir validate` 拒绝（`_validate_removed_fields` 保持），给出指向 `matte` 的迁移指引。
7. **`CACHE_VER v7 → v8`**（渲染缓存语义变，旧 segcache 全失效）。

## 取舍

- 付出：重依赖（~480MB）；首次使用有下载；新字段进契约，渲染／IR／schema／verify／剪映降级标注都要动。
- 换来：抠像质量有**客观锚点**，不再是「感觉不行就砍掉」；短剧／解说类表现力解锁；ADR-0031 默认行为不变（风险可控）。

## 被否决的替代

- **永久维持 ADR-0031（永不抠像）**：否决——用户已明确要求重建，且新类型强依赖。
- **复用 ADR-0031 删掉的键控链路**：否决——那条路的天花板是 ADR-0031 自己记录的事实。
- **对流式类型默认开启自动抠像**：否决——会把懒加载的重模型变成事实上的必装项，且违反「默认不变」的迁移友好原则。

## 影响

- `rs_render`（消费 `matte`）、`rs_ir`（校验）、`project.schema.json`（新增 `matte` 定义）、`rs_verify`（L0 加抠像质量判据）、`rs_jy_draft`（剪映不支持该抠像时如实降级标注）、`rs_diagnose`。
- `rules/video-types/*.md` 中所有「已由用户自行抠像并合成背景」的表述改为「按 S0 分流决策」。
- `rs_intent` 的 `brief` 新增 `autoMatting` 布尔（`decision_log` 留痕）。

## 四问

| 问 | 答 |
|---|---|
| 旧工程 | 无 `matte` 字段 → 行为完全不变；带 `chroma`/`background` → 仍报错并要求迁移；`CACHE_VER` 变化 → 旧 segcache 自动失效重建（不损坏数据）。 |
| 门禁 | `tests/test_matting.py`：①五项指标在合成夹具（干净／毛边／抖动三组）上判定正确；②`FAIL` 必须阻断且非零退出；③`WARN` 必须进交付说明；④`CACHE_VER == 8` 断言。 |
| 验收 | 三段真实素材（绿幕口播／复杂背景人物／低分辨率）跑门禁 → 干净素材 PASS、劣质素材 FAIL；PASS 素材走完整管线出片并过 L0。 |
| 回滚 | `config.auto_matting = false` + `rs_fetchable rollback vision.matting`；已产出带 `matte` 的工程需 `rs_run --from S3 --force` 重跑（`matte` 被忽略后即回到原行为）。 |
