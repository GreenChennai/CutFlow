# ADR-0006:双声源架构(原声口播 / 音色卡纯声音视频)

状态:已采纳 ｜ 日期:2026-09-07

## 背景

EchoSmith 与 EchoRunner 已合并为 EchoSmith(现以 Skill 形态存在于 E:\平日资料\GitHub\EchoSmith),Jimi 音色已用新数据重训(注意:card.json 的 sovits 路径曾过期,已修正为 Jimi_e8_s552.pth;参考音频 clip_197 超出引擎 3–10s 限制,已换 clip_031 + 对应转写)。用户要求尝试"纯声音视频":不用原素材画面,仅用 Jimi 配音 + 文案。

## 决策

1. 声源在 brief 里二选一或显式混用:`voice=original`(口播原声)/ `voice=<音色卡>`(TTS,默认 koubo-test,可指定 Jimi);
2. **成片 A**(口播精修)= 原声 + 绿幕人像 + 虚拟背景 + 穿插卡 + 字幕 + 音效;
3. **成片 B**(纯声音视频)= 音色卡全文案配音 + artboard 动画场景串联 + 字幕 + 音效,无真人画面;场景切换点对齐 TTS 句级时间轴(manifest start/end);
4. TTS 稿允许**轻改写**(口语冗余合并、标点规范化),因为成片 B 里音频就是 TTS 新生成的,字幕与音频天然同源——这与 ADR-0002"音频不动"不冲突(那是对原声口播的约束)。

## 后果

- 一次转写,两条产物路径复用;音色卡机制天然支持后续新音色;
- 成片 B 的时长由 TTS 实际合成时长决定(约 19–29s/句,ZLUDA),句间 120ms 垫片;预期能耗大,须全量落盘断点续传(rs_tts 已支持);
- Jimi 卡的参考音频约束(3–10s)进入 EchoSmith 侧已知问题——卡片校验应加时长检查(记 BACKLOG)。
