# ADR-0037: N 后端注册表取代"两种消费者"

日期: 2026-09-17 · 状态: 已采纳 · 关联: ADR-0034(五份 schema)、ADR-0038(渲染后端能力对等边界)

## 背景

CutFlow 既有模型把 IR 的消费者写死为两个:`CONTEXT.md` 原文"IR 的两种消费者——FFmpeg 后端(rs_render)与剪映后端(rs_jy_draft)",SKILL.md §8 称"双通道"。CutForge 渲染后端(cutforge-render)是第三个消费者;若按"两种"的字面模型继续加,每加一个后端都要改契约与文档,模型不可扩展。

## 决策

1. **N 后端注册表**:IR 的消费者集合开放注册,每项带稳定 `backendId`;契约层不再出现"两种/双通道"的封闭表述。
2. **声明进契约**:project v2 schema 新增 `backends: array[string]` 字段(枚举 `ffmpeg` / `jianying` / `cutforge`),工程显式声明启用了哪些后端;未知值因 `additionalProperties: false` 与枚举封闭而报错,扩集必须先升 schema。
3. **能力矩阵代替口头承诺**:每个注册后端在能力对等矩阵(docs/capability-matrix.md,ADR-0038)中逐项声明支持程度,不做隐式假设。
4. **Golden 基准不变**:`ffmpeg` 后端始终可用且是对拍基准;任何新后端(含 cutforge)不得取代其地位。
5. **文档同步**:CONTEXT.md「时间线与渲染」改为"N 后端注册表"表述并新增「CutForge 与同步」分区;全文检索"两种消费者"命中数 = 0(M1 门禁)。

## 后果

- 正面:新增后端(未来 CLI 预览器、音频only 导出等)只登记不改契约;三个既有后端地位与边界显式化。
- 代价:旧文档中"双通道/两种消费者"的表述全部过时,需要一次性清理;backends 字段对旧工程缺省(迁移器补默认 `["ffmpeg"]`,由读取方按缺省语义处理)。
- 兼容:`rs_ir`/`rs_render`/`rs_jy_draft` 行为不变——它们仍是注册表中的既有成员,只是不再被文档定义为"仅有两个"。

## 替代方案

- **写死第三后端(加常量 CUTFORGE=3)**:否决——同构问题后移,第四个后端到来时重演。
- **后端即插件、运行时注册无 schema 约束**:否决——枚举封闭原则(计划书 1.1 原则 6)要求先改 schema 再扩集,防止半成品后端混入契约。
