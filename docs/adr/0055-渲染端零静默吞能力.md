# ADR-0055: 渲染端「零静默吞能力」——声明与实现强制对齐

日期: 2026-09-26 - 状态: 已采纳(v0.20 已落地) - 来源: 《CutFlow-迭代计划-v2-20260925》主册 §3(转写自桌面蓝本,以蓝本为权威)

**状态**：已采纳(v0.20 已落地) · **关联**：v1 ADR-0054 家族（契约唯一）、分册03 发现 #2

#### 背景

分册03 抓到 4 处**声明支持但渲染端静默无效**：

| 声明处 | 实际 |
|---|---|
| `project.schema.json` 的 `motion.in` 含 `scaleIn`/`zoomIn` | 基轨**退化为 fadeIn + 警告**；overlay 轨**无实现（静默）** |
| 同上的 `motion.out` 含 `slideOutLeft`/`slideOutRight` | 基轨与 overlay 轨**均无实现** |
| `motion.in: slideInLeft/Right` | 仅 overlay 轨有实现；基轨退化 |
| `project.schema.json` 的 `bgm.loop: false` | `rs_render.py:817` 无条件 `-stream_loop -1`，**忽略该字段** |

另有转场 `cut`/`none` 在 schema 合法却**过不了 `rs_ir.validate`**（`rs_ir.py:35` 的 `TRANSITIONS` 不含它们）。

#### 决策

1. **逐字段审计**：对 `project.schema.json` 的**每一个**枚举/字段，产出「声明 → 消费者 → 行为」三列清单，标记 `已实现` / `未实现` / `部分实现`。
2. **未实现的一律二选一**（不允许留在中间态）：
   - **实现**（v2 优先补齐 `motion` 的 5 个空壳：`scaleIn`/`zoomIn`/`slideOutLeft`/`slideOutRight` + 基轨的 `slideIn*`）；
   - **从 schema 删除**（若判定不做）。
3. **警告不算实现**：`rs_render` 里的「退化为 fadeIn + 警告」在审计中一律算 **未实现**，必须走到第 2 条的结论。
4. **新增门禁**：`tests/test_schema_consumers.py` —— 对 schema 里每个 `enum` 值，断言渲染端**要么实现、要么在 `UNIMPLEMENTED` 白名单里显式登记**（白名单本身也是债，必须逐条给理由与里程碑）。
5. **`bgm.loop`**：按其声明实现（`loop:false` 时不加 `-stream_loop -1`）。

#### 取舍

- 付出：一次全 schema 审计；补齐 5 个 motion 实现。
- 换来：**再也不会有「配置写了没反应」**——这是用户信任的基础设施。

#### 被否决的替代

- **只在文档里标注「部分实现」**：否决——用户与 Agent 都不会读 schema 的实现注记，仍然是静默。
- **把未实现项从 schema 删掉但保留在文档**：否决——文档与契约两套说法正是 v1 §1.8 的病根。

#### 四问

| 问 | 答 |
|---|---|
| **旧工程怎么办** | 被删除的 schema 值：旧 IR 若使用 → `rs_ir validate` 报错并给替代值映射；被实现的字段（如 `bgm.loop:false`）**行为变化必须写 CHANGELOG**（从「忽略」变「生效」属行为变更）。 |
| **门禁怎么把守** | 第 4 条的 `tests/test_schema_consumers.py`；`UNIMPLEMENTED` 白名单只允许短期存在且必须带 `reason` + `milestone`。 |
| **怎么验收** | 三列清单零 `未实现`（除白名单）；白名单条目数 ≤3 且每条有里程碑；`motion` 5 个空壳有渲染冒烟测试。 |
| **怎么回滚** | 纯 schema/渲染端改动；回滚即还原 `project.schema.json` 与 `rs_render.py`（`bgm.loop` 行为变更需在回滚说明里注明）。 |
