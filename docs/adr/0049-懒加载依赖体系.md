# ADR-0049: 懒加载依赖体系 —— 初始零环境，用到才下载

日期: 2026-09-25 · 状态: 已采纳（待落地） · 关联: ADR-0008（修订）、ADR-0015（ASR 自举）、ADR-0050

## 背景

现有 `fetch_deps.py` 已支持 `ocr`（~113MB）／`vqa`（~630MB）／`asr --onnx`（~200MB）／`asr --pkg`（~1–2GB）四类模块，按需部署并回写 `config`，还带 `--seed-models`（目录联接零拷贝）、`--update-vendor`（覆盖推理层）。**这是懒加载的雏形**，但：

- 没有「能力 → 组件」映射（用户不知道「卡点」需要什么）；
- 没有版本与更新检查；
- 没有统一的「缺失 → 降级 + 留痕」三态协议；
- `rs_doctor --report` 与它没有双向联动。

而 ADR-0031 之所以把整条抠像链砍掉，本质是**重依赖与克制纪律僵持**——懒加载正是这个僵局的解。

## 决策

1. **新增 `scripts/rs_fetchable.py`**：能力 → 组件映射与三态管理。

```python
CAPABILITY_DEPS = {
    "audio.beat":     {"modules": ["beatnet"],     "size_mb": 320, "backend": "venv-dsp",
                       "probe": "import beatnet",  "degrade": "onset-energy"},
    "audio.downbeat": {"modules": ["madmom"],      "size_mb": 210, "backend": "venv-dsp",
                       "probe": "import madmom",   "degrade": "beat-only"},
    "audio.stem":     {"modules": ["demucs"],      "size_mb": 350, "backend": "venv-dsp",
                       "probe": "import demucs",   "degrade": "none"},
    "vision.shot":    {"modules": ["scenedetect"], "size_mb": 45,  "backend": "py",
                       "probe": "import scenedetect", "degrade": "frame-diff"},
    "vision.matting": {"modules": ["rvm"],         "size_mb": 480, "backend": "venv-torch",
                       "probe": "import torch; rvm",  "degrade": "none(gate)"},
    "vision.track":   {"modules": ["bytetrack"],   "size_mb": 20,  "backend": "py",
                       "probe": "import bytetrack","degrade": "static-center"},
    "vision.cv":      {"modules": ["opencv"],      "size_mb": 60,  "backend": "py",
                       "probe": "import cv2",      "degrade": "none"},
    "text.clip":      {"modules": ["clip"],        "size_mb": 600, "backend": "venv-torch",
                       "probe": "import clip",     "degrade": "keyword-match"},
}
```

2. **三态协议**：`MISSING`（缺失）→ `FETCHING`（下载中，可中断续传）→ `READY`（可用）／`FAILED`（失败降级）。任何一笔消费能力的操作，先查三态：

| 态 | 行为 |
|---|---|
| `READY` | 正常执行 |
| `MISSING` + 允许下载 | **现场下载**（进度可见），成功后转 `READY` |
| `MISSING` + 不允许（离线／`--no-fetch`／用户拒绝） | **降级到描述符声明的 `degrade` 档**，产物与报告写 `degraded: true` + `degradeReason` + `missingComponent` |
| `FAILED` | 同上降级，并保留失败日志路径供 `rs_doctor` 展示 |

3. **初始零环境是硬承诺**：`rs_doctor --report` 在**未部署任何可选件**时必须报「基础档可用」（FFmpeg + 纯标准库路径），不得报 fatal。
4. **下载过的保留不删**；提供 `rs_fetchable.py update [--check|--apply]` **触发式更新**（比对本地版本与远端清单）。**不自动更新**（避免不可复现）。
5. **`rs_doctor` 联动**：`--report` 末尾列「已部署能力／缺失能力 → 影响哪些 videoType 与手法」。
6. **存储位置统一**：`tools/deps/<module>/`；重依赖走**独立 venv**（`tools/.venv-dsp`、`tools/.venv-torch`）**避免污染主解释器**——沿用 `tools/.venv-asr` 的既有模式。

## 取舍

- 付出：首次使用某能力时有下载等待；需要维护远端清单与版本。
- 换来：冷启动零负担；重依赖按需；能力缺失**永不静默**；抠像这类重能力可以重新立项。

## 被否决的替代

- **全部预装**：否决——违背克制纪律，部署门槛爆炸。
- **全部自研轻量版**：否决——精度上限受限（参见 §5.9 对「卡点」的精度要求）。
- **运行时 `pip install` 到主解释器**：否决——会污染环境、破坏可复现性，且 `asr` 的历史事故已证明主解释器不该装重依赖。

## 影响

- `tools/fetch_deps.py` 保留（兼容入口），内部委托 `rs_fetchable`。
- 新增 `rules/deps-lazy.md`（能力／组件／降级／留痕规范）。
- 每个产物 JSON 增加可选 `degraded` 块（**向后兼容：旧消费者忽略未知字段**）。

## 四问

| 问 | 答 |
|---|---|
| 旧工程 | 无 `degraded` 字段即视为未降级；`rs_doctor` 报「未部署可选件」不影响旧流程。 |
| 门禁 | `tests/test_fetchable.py`：①映射表每个 `probe` 语法可执行（不真装）；②缺失时降级路径必须写留痕（mock 缺失）；③离线模拟（`--no-fetch`）不得触发网络；④`rs_doctor` 在零环境下非 fatal。 |
| 验收 | **清空 `tools/deps/` 后**，四型基础档端到端可跑；触发高级能力时正确下载并转 `READY`；断网时正确降级且留痕。 |
| 回滚 | 删除 `tools/deps/<module>/` 即回到缺失态；`config` 回写项由 `rs_fetchable rollback <module>` 清理。 |
