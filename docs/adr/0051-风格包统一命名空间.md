# ADR-0051: 风格包统一命名空间（CutFlow ↔ artboard 共用 slug）

日期: 2026-09-25 · 状态: 已采纳（待落地） · 关联: ADR-0040（风格注册表）、ADR-0017（artboard 桥）、artboard `references/style-guide.md`

## 背景

- CutFlow 侧：风格 = `registry.json` 的 `entries[]` 条目 + `templates/styles/<style>.yaml`（现有 `talkshow-bold` / `tutorial-clean` / `motion-info`）+ `rules/video-types/<type>.md` 分册。
- artboard 侧：风格 = `references/styles/<slug>.md` + `assets/cases/<slug>-case.html` + `SKILL.md` 清单表**三处同名**。

**两套体系互不认识**，导致片头尾的视觉风格与正片对不上（用户明确诉求 G7）。而 artboard 的机制（文档分册 + 案例 + 清单表，运行时零代码）**正是 CutFlow 要的形态**。

## 决策

1. **引入「风格包」为唯一封装**：`templates/styles/packs/<slug>/`，一个风格包 = **参数档 + 分册 + 卡片案例 + 参考片**。

```json
{
  "slug": "knowledge-talkshow-douyin",
  "label": "知识口播·抖音竖屏",
  "videoType": "talking-head",
  "params": "packs/knowledge-talkshow-douyin/params.yaml",
  "rule": "rules/video-types/纯口播.md",
  "capabilities": [],
  "artboard": {
    "styles": ["tech-kv"],
    "cases": ["assets/cases/tech-kv-case.html"],
    "templates": ["opener:1", "title:3", "endcard:1"]
  },
  "reference": "docs/reference/knowledge-talkshow-douyin.md"
}
```

2. **`registry.json` 的 `entries[]` 降级为「风格包的索引 + 匹配关键词」**，真正的参数迁入 `packs/<slug>/params.yaml`。**保持 `registry.json` 既有键名与结构不变**（`rs_intent` 继续工作），只把 `style` / `styleTemplate` 指向 pack。
3. **CutFlow 与 artboard 共用 slug 命名空间**：
   - CutFlow 风格包 slug 采用与 artboard 风格 slug **同构的命名法**（`<领域>-<调性>`）；
   - 一个 CutFlow 风格包可**引用 1–2 个 artboard 风格 slug** 作为卡片视觉来源（沿用 artboard 的「章节原子化、一次借 1–2 个原子」纪律）。
4. **三处同名对拍门禁**：一个风格包必须同时具备 `packs/<slug>/params.yaml` + `rules/...` 引用 + `artboard.styles` 引用的**真实存在**；缺失即红。**不允许「文档有、参数无」或反之。**

## 取舍

- 付出：风格定义从「一个 JSON 文件」拆成「一个目录」；`rs_intent` 需适配。
- 换来：风格真的一处定义、多处消费；片头尾与正片视觉天然一致；新增风格 = 加目录 + 加一行，**零代码**（与 artboard 完全同构）。

## 被否决的替代

- **直接复用 artboard 的 `references/styles/` 作为唯一风格源**：否决——artboard 风格是「平面设计」语境（画布／色板／字体栈），不含视频节奏／BGM／字幕／CPS 参数，维度不匹配。
- **各自维护两套风格**：否决——正是现状的病因。
- **强制 slug 完全同名（一一对应）**：否决——两者维度不同（视频风格 ≠ 海报风格），强行同构会造出无意义空壳。**共用命名空间 ≠ 一一对应**。

## 影响

- `templates/styles/packs/` 新增；`registry.json` 加 `pack` 字段；`rs_intent` 改为「读 registry → 定位 pack → 读 params.yaml」。
- 新增 `scripts/rs_stylepack.py`（加载／校验／slug 一致性检查）。
- artboard 侧**只读引用，不改动**（遵守工作区 AGENTS.md：不动第三方参考；artboard 属用户的技能资产，若要在其中加 CutFlow 对接页，须用户显式点头——见 §9）。

## 四问

| 问 | 答 |
|---|---|
| 旧工程 | 旧工程只记 `styleName`（`entries[].id`）；pack 缺失时按 registry 原路径回退 + WARN `stylePackMissing`，行为不变。 |
| 门禁 | `tests/test_stylepack.py`：①每个 pack 的 `params`／`rule`／`artboard.styles`／`artboard.cases` 路径真实存在；②slug 命名法校验；③「文档有参数无」双向对拍；④`rs_intent` 在 pack 全备／缺失两种输入下都产出可复现结果。 |
| 验收 | 新增一个风格包（如「短剧·高燃竖屏」）**只加目录 + registry 一行**，`rs_intent compile --dry-run` 即可产出该风格全参数；片头卡自动取对应 artboard 风格。 |
| 回滚 | pack 缺失自动回退 registry 原路径；删目录即回滚。 |
