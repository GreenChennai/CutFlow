# ADR-0007:工程归档与命名规范(中文 + 日期 + 关键词,测试件完工即清)

状态:已采纳 ｜ 日期:2026-09-08

## 背景

v0.2 验收时工程目录混乱:`dev-test` 等英文测试名、测试小样/中间件/正式产物混放、完工后垃圾留存。用户要求"规范项目的文件存放和归档方式,使用中文命名,辅以关键词和日期归档;测试文件完工后删除"。

## 决策

1. **工程目录名**:`<YYYYMMDD>-<中文标题>-<类型关键词>`,如 `20260908-店群运营拆分收入-口播绿幕`。类型关键词 ∈ {口播绿幕, 口播, 纯文案, 动画教程, 新闻采访, 短剧, 影视解说}。
2. **内部结构**不变(00_brief…06_output,见 PLAN.md §10);**用户可见产物用中文命名**:`成片_竖版_最终.mp4` / `成片_横版_最终.mp4` / `封面.png` / `字幕.srt` / `配音稿.txt`;**内部中间件保持 ASCII**(seg_0001/base/composed——ffmpeg filter 转义安全)。
3. **测试件铁律**:临时试验一律放 `dev-` 前缀文件或 `99_试算/` 目录;**交付前必须跑 `rs_cleanup.py`**——默认 dry-run 列清单,`--apply` 才真删;必删:06_output/_build、dev-*、*_probe*、试算目录;必留:brief、文案、转写校对稿、成片、封面、字幕、project.md。
4. 旧工程迁移:旧英文名工程一次性重命名归档。

## 后果

- 资源管理器按日期+类型一目了然;中文命名仅用于用户产物,渲染链路零风险;
- 清理是显式脚本而非人肉,可 dry-run 预览,防误删。
