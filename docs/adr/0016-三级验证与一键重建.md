# ADR-0016:三级验证与手工编辑工作流

状态:已采纳 ｜ 日期:2026-09-10

## 背景

用户要求两件事:

1. 「首次剪辑的时候才运行检查,检查完毕→有问题→修复→检查→没问题→完成;之后用户有要求修改……修改之后也不用再次检查,只运行代码部分的自检即可,剩下的实际检查交给用户来完成,触发用户要求你检查」;
2. 「允许用户手动修改阶段……在那个文件夹里面应该有一个 Python 脚本,能够一键启动并检查,然后连带触发其他脚本,最终重新合成导出成完成视频」。

## 决策

### 一、把"检查"拆成三级,各归其主

| 级别 | 名称 | 谁执行 | 何时跑 |
|---|---|---|---|
| **L0** | 机械自检 | 纯脚本 | **每一次**产出后 |
| **L1** | 语义自检(看图) | Agent | **首次**;或画面构图变更时 |
| **L2** | 人工验收 | **用户** | 由用户显式触发 |

- L1 的**触发权**在首次,L2 的**所有权**在用户;**Agent 不得主动发起 L1**;
- "画面变了"不靠 Agent 猜:`rs_run --verify` 比对 `_state/S3|S4|S5.json` 的失效状态;
- **`missing`(从未记录)不算变更** —— 那只是阶段没跑过,不代表画面变了。只有做过且失效(`stale/failed`)才算。

### 二、输出契约(硬规则)

任何交付输出**必须**携带 `verifyLevel` 与 `firstCheckDone`。**缺失即视为未验证,不得宣称"完成"。**

> 这条针对一个具体的坏结果:「之后不用检查了」被实现成「之后什么都不检查」,而界面还显示一个漂亮的 ✓。

### 三、新增 S8「烧录导出」阶段

实施中发现:若没有独立的烧录导出段,`06_output/rebuild.py` 只能从 S7 起跑,而 S7 会**重新生成 `subtitles.ass`** —— 用户手改的字幕会被冲掉。

所以把 S8 定义为「**用现有 ass 重新烧录并导出**」,阶段表扩为 **S0–S11**(12 段,仍在上限内)。手改字幕 → `06_output/rebuild.py` → `--from S8 --force`。

### 四、一键重建与备份

`rs_run.py --init` 在每个阶段文件夹生成 `rebuild.py`(薄壳)+ 根目录 `REBUILD.md` 速查表。每个脚本固定四步:

```
备份 → 校验 → 级联(--force 只作用于起点,上游走缓存)→ 导出 + 自检
```

- **先备份**:用户手改的可能是产物,重跑会覆盖它。备份到 `_state/backup/<ts>/`,保留最近 5 次,`--rollback` 可还原;
- **先校验**:JSON/IR/ASS/guard 任一不过就**停住并指出具体行**,绝不带着坏输入往下跑;
- **`--force` 只作用于起点**:上游仍走缓存,这是"改字幕只要几秒"的前提。

## 后果

- 改字幕的往返从"重跑 20 分钟 + 人工复检"变成"秒级 L0 + 用户自己看一眼";
- 阶段表从 11 段变 12 段,文档与测试同步更新(有测试强制覆盖);
- 备份会占磁盘,已用保留 5 次的策略约束;
- 新增一类必须监控的失败模式:脚本"看起来跑通了但没验证" —— 由输出契约字段兜住。
