# ADR-0035: 与 OpenCut 的关系——借鉴领域模型、不搬运代码、MIT 归属并存

日期: 2026-09-17 · 状态: 已采纳 · 关联: ADR-0036(ARL-1.0 混合授权)、《融合迭代计划书》附录 C

## 背景

CutForge 的领域模型参考上游 OpenCut 两仓:`OpenCut-app/OpenCut`(MIT,**活跃重写中**,crates/* 尚未落地、PR 政策 collaborators_only,当前无可对接的内核 API)与 `OpenCut-app/opencut-classic`(MIT,2026-05-17 归档,唯一跑通过的完整编辑器领域模型)。必须事先定死"借鉴什么、不碰什么",否则许可归属会在发布后变成不可回退的麻烦。

## 决策

1. **只读参考,不搬运任何代码**:不复制 classic 与主仓的任何 `.ts`/`.tsx`/源文件、brand 资源、changelog;只借鉴领域模型与交互设计(时间线、轨道、元素、命令与撤销、工程持久化等概念划分)与工程配置形状(工具链 pin、目录划分)。
2. **工具链与结构对齐**:`proto + moon + bun + rust 1.97.0`、edition 2024、resolver 3,与上游一致,保留未来接口层回流上游的零摩擦可能。
3. **MIT 义务照单全收**:两仓的 MIT 许可全文逐字保留于 `LICENSE-OPENCUT.MIT`(1,060 字节原文,未改一字);`NOTICE.md` 如实声明"参考了其设计",并声明 CutForge 与 OpenCut 无隶属/背书关系。
4. **升级为"派生"的门槛**:若确需引用上游具体代码片段,必须文件头标注来源(URL+路径+SHA)、补 ADR、更新 NOTICE、该文件不适用 ARL-1.0。默认预期:不需要。
5. **红线**:不得以 `OpenCut`/`opencut` 命名产品、仓库、包、域名;对外文档不得把主仓描述为"停更"(它活跃重写中;归档的只是 classic,且必须写明日期)。

## 后果

- 正面:拿到 classic 的成熟领域模型,同时把许可义务降到最小(只需 NOTICE 归属声明,无需承担"分发其代码副本"的义务);避免照抄已归档 TypeScript 代码引入的混合授权复杂度与无意义移植成本。
- 代价:实现速度让位于许可清洁度——Rust 重写等于把 classic 的行为自己再实现一遍。
- 事实约束:上游若开放外部贡献或 crates/* 落地,我们不主动追赶,只在接口层面保持兼容(风险登记册 R1)。

## 替代方案

- **Fork classic 改造**:否决——TS 技术栈与 Rust 目标相悖,且继承归档代码的全部未修问题,Fork 身份还锁死改名与独立发布的诉求。
- **只做上游插件、等其 Editor API**:否决——上游当前无任何可对接 API(crates 仍注释、api 仅 3 路由、PR 仅 collaborators),等待不可控。
- **引用 classic 具体算法实现以加快进度**:默认否决——非平凡算法自己重写一遍通常可行;确需引用时走第 4 条升级流程。
