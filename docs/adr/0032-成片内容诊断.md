# ADR-0032: 成片内容诊断(rs_diagnose)—— 从成片出发的独立证据链

日期: 2026-09-16 · 状态: 已采纳 · 关联: ADR-0016(分级验证)、ADR-0021(失败语义)、docs/REVIEW-20260916-假正常诊断根因.md

## 背景

用户报告:成片存在字幕错位/口型错位/错剪无意义片段,Agent 探查一两小时后仍回复
"完全正常"。根因审查(docs/REVIEW-20260916)定位五环根因链,核心一条:

> **所有机器闸都是「对照中间产物」的闸;错误发生在管线内部时,错误同时传染给
> wordline/ass/成片,所有对照闸拿到同一份错误的镜像,互相印证,全部绿灯。**

仅有的两个对照成片实际内容的闸(B10 音频内容闸 / QC 体检)是 opt-in,且 B10 只做
文本级相似度,无时间轴对账。

## 决策

新建 `rs_diagnose.py`:**从成片出发的独立证据诊断**。原则:

1. **独立证据源**:所有判据从成片(视频+音轨)现场测量,不采信工程中间产物;
   中间产物(wordline/ass)只作为**对照参考**,且对照差异本身就是检测目标;
2. **每个结论带时间段+证据**;判不了的显式输出"无法机械判定"+疑点清单,
   禁止无证据的"完全正常";
3. **台账留痕**:每次诊断写入 `06_output/diagnosis/diagnosis_log.jsonl`,
   误判可复盘到检查项级;
4. **耗时预算**:默认 `--budget 900s`;超时输出阶段性结论+已完成的检查,
   绝不空手说"没问题"。

## 三类缺陷的检测设计

### D1 字幕 ↔ 语音错位

**原理**:对成片音轨独立跑自带 ASR(本仓 tools/fun_asr.py),得到"成片里实际
说出的每个字+时间戳";对成片字幕有两条独立通道——ASS 文件(若工程提供,仅作
参考)与视频 OCR(可选)。核心比对是**成片 ASR 时间轴 ↔ ASS 时间轴**:

- 文本匹配:difflib 对齐 ASR 串与 ASS 串,定位每张卡的对应字区间;
- 偏移 = ASS 卡起点 − ASR 对应首字起点(毫秒);
- 判定(经验阈值,回归集校准):`|median offset| > 120ms` 或
  `p95 > 250ms` 或 `任一卡 |offset| > 500ms` → FAIL,报告逐卡偏移表;
- **无法判定**:ASR 失败/文本对不上(匹配率 <60%)→ 状态 `indetermined`,
  列出未匹配区间,不放行"正常"。

**证据**:逐卡偏移表(卡文本/ASS 起点/ASR 起点/偏移 ms)+ 最差 3 张卡的时间段。

### D2 口型 ↔ 声音错位(音画同步)

**原理**(机械可判、肉眼级):对成片双通道采样——

- 音频活动:RMS 包络(10ms 窗)的活跃掩码(语音开始/结束事件);
- 画面运动:抽帧灰度差分(抽 12fps,整帧下采样 64×36 后 L1 差分)的运动能量曲线,
  在每个音频事件邻域找画面运动的峰;
- 对每个"语音事件",计算画面运动峰相对语音起点的延迟 δ;口型同步时 δ 集中在
  0-±100ms;音画错位时 δ 呈现一致偏移(音轨提前/滞后)。

判定:`|median δ| > 200ms`(肉眼可辨阈值)→ FAIL 报"音画整体错位约 X ms";
`p95 > 450ms` → FAIL 报离散错位时间段。**纯动画/无人物画面**会被此检测误报,
因此 D2 在工程 IR 声明 `pure-animation` 时自动跳过(留痕),成片级诊断无 IR 时
输出 `indetermined` 而非 FAIL——**"无法判定"必须显式,这是本 ADR 的铁律**。

**证据**:δ 分布(median/p95/n)+ 违例事件的时间段清单 + 抽帧运动曲线 PNG(可选)。

### D3 错剪 → 无意义片段

两个互补检测:

**D3a 剪点上下文审计**(有工程 cutlist 时):对每个 remove 刀,取切点前后各
1.2s 的源文本(词级),检查:① 切点前句是否以句号/问号收尾(句中腰斩 → 疑点);
② 切点后句是否以连接词开头(「然后/但是/所以」开头但前文被剪 → 语义悬空);
③ 前后保留片段合计 <1.5s 的"碎片保留"。命中 → `suspicious` 列表(时间段+原因)。

**D3b 成片语义连贯**(独立于工程产物):成片 ASR 文本分句后,检查
① **无意义重复**:相邻句相似度 >0.85 且 <完全相同(半句重放特征);
② **悬空连接词**:句首连接词且前一句以句号收尾的密度异常(>15%);
③ **突兀截断**:句间静音 <80ms 且前句无标点(腰斩感)。
命中 → suspicious 时间段 + 文本证据。

判定:D3a 任一命中 → WARN(需人看,给时间段);D3b ≥2 处命中 → FAIL;
1 处 → WARN。全部无命中且 ASR 可用 → PASS 带证据(匹配率/分句数);
ASR 不可用 → `indetermined`。

## 输出契约

```
{"ok": bool, "code": "DIAGNOSIS_OK|DIAGNOSIS_ISSUES|DIAGNOSIS_INDETERMINED",
 "verdict": "pass|issues|indetermined",       # 三态,没有含糊的"正常"
 "checks": [ {"id": "D1", "name": "...", "status": "pass|fail|warn|skipped|indetermined",
              "elapsedS": 12.3, "findings": [...], "evidence": {...}} ],
 "suspiciousSpans": [[12.4, 15.8], ...],       # 疑点片段清单(用户可跳着看)
 "elapsedS": 812.4, "budgetS": 900,
 "ledger": "06_output/diagnosis/diagnosis_log.jsonl"}
```

- `verdict=pass` **必须**所有可用检查 pass 且至少跑过 D1/D3 之一;超时降级时
  verdict 至多为 `indetermined`,并在 `partialChecks` 列出未完成项;
- 台账 JSONL 每行一次诊断:时间戳/输入/各检查 status+elapsedS+findings 摘要/
  verdict/版本(脚本 git hash 或 DIAG_VERSION)。

## 与现有链路的集成

- `rs_verify.py` 新增 `--content`:L0 之外追加调用 rs_diagnose(受预算约束),
  输出 `contentVerdict`;**L0 通过的语义显式降级**为 `scope: mechanical`
  (报告与 JSON 双写),堵住"把机械自检说成内容没问题"的表述漏洞;
- 独立入口:`python rs_diagnose.py <成片.mp4> [--project <工程根>] [--ass ...]
  [--cutlist ...] [--budget 900]`——历史视频/外部视频也能诊断(不需要工程根);
- ASR 复用 `rs_align._from_media`(自带 fun_asr,`--backend auto`);
- 复用 `rs_sync.check_offsets` 的文本匹配思想,但比对对象换成**成片实测**。

## 阈值校准策略

初值按经验(肉眼可辨口径)设定;`tests/test_v14.py` 的注入缺陷回归集
(错位字幕 ±350ms/错位音轨 ±400ms/错剪腰斩)作为校准锚:每类缺陷至少一个
量级必须被检出,正常视频不得误报。阈值以常量定义于脚本头部,集中可调。

## 回滚

- `rs_diagnose.py` 为新增文件,删除即回滚;
- `rs_verify --content` 为 opt-in,L0 默认行为仅"语义降级表述"一处修改,
  revert 单提交即可;
- 台账为纯增量 JSONL,不影响任何现有产物。
