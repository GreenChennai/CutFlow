# ADR-0033: 文件为真相源 + 操作日志双向合并

日期: 2026-09-17 · 状态: 已采纳 · 关联: ADR-0013(内容寻址缓存)、ADR-0037(N 后端注册表)、《CutForge × CutFlow 融合迭代计划书》第 4 部分

## 背景

CutFlow 与 CutForge 双向打通后,同一份工程文件(05_ir/project.json 等)会有两类写入者:CutFlow 管线(AI/脚本)与 CutForge 编辑器(人)。必须回答"谁是权威":若编辑器持有独立权威文档,则 CutFlow 全部 S0–S11 输入层(1.1–1.2 万行,经 15 个版本实测打磨)都要重写,且阶段缓存键(`rs_run.py` 的 `stage_parts()`)建立在"输入是文件"的前提上,风险最高、收益最低;若只做"编辑即全量写回"的单向前端,并发编辑互相覆盖、无变更粒度、无法 diff,双向同步退化为最后写入者获胜。

## 决策

**文件是真相源;编辑器不持有独立权威文档。** 任何写入者(用户编辑器 / AI / 脚本 / 桥脚本)必须走唯一写入路径:

1. 申请工程锁(cutforge-io::lock);
2. 生成 Op(含 `baseRev` = 当前 rev);
3. 校验 Op 前置条件(针对 baseRev)——失效则**不写入**,转入显式冲突流程(CF-001~CF-006);
4. Op 追加写入 `.cutforge/oplog/YYYYMMDD.jsonl`(append-only,按天切分);
5. 应用到内存模型生成新文件内容,原子写入(临时文件 + rename);
6. rev 单调递增写 `.cutforge/rev`,释放锁并广播变更事件。

合并采用**三路 diff**(祖先/磁盘/内存,以 baseRev 为共同祖先),字段级(叶路径)粒度,共 9 行判定表;结构级冲突一律交人/AI 裁决,禁止自动挑边。

## 后果

- 正面:并发改动可检测、可合并、可审计;"静默覆盖数 = 0"成为可门禁的硬指标;AI 改动天然可 diff、可撤销(undo 也是 Op)、可回放(OpLog 回放 ≡ 当前状态)。
- 代价:所有写入必须收敛到命令通道,不允许任何旁路直接写文件;Op 必须带 baseRev 与幂等保护(同 opId 去重);`.cutforge/` 成为可安全删除重建的运行时状态(仅丢同步历史)。
- 边界:CutForge **不实现任何 S0–S11 业务逻辑**,只做"改文件 + 提示/触发重建 + 展示结果";阶段缓存的 stale 语义保持 CutFlow 既有实现不动。

## 替代方案

- **编辑器工程为真相源**:否决——需重写 CutFlow 全部输入层,缓存键前提崩塌,风险最高收益最低(见背景)。
- **单向真相源(编辑只是可视化 + 全量写回)**:否决——并发覆盖、无变更粒度、无法有意义地 diff。
- **最后写入者获胜(无 baseRev)**:否决——无法三路合并,静默覆盖不可检出,违反北极星指标。
