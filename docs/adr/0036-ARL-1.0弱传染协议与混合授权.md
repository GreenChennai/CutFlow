# ADR-0036: 采用自定义弱传染协议 ARL-1.0 与混合授权布局

日期: 2026-09-17 · 状态: 已采纳(协议文本正式发布前须执业律师复核) · 关联: ADR-0035(OpenCut 只读策略)、《融合迭代计划书》附录 A/B

## 背景

CutForge 需要一个自定义协议,既要保护核心(编辑器内核被修改后能回传开源),又不妨碍插件/壳/商业应用生态。候选家族:宽松型(MIT/Apache-2.0,核心修改可闭源)、弱传染型(MPL-2.0 精神,文件级互惠)、强传染型(GPL/AGPL,整作品互惠)。另外既有事实必须兼容:CutFlow 已按 MIT 发布 v0.1.0–v0.12 等 tag;OpenCut 派生部分必须继续遵守 MIT。

## 决策

1. **原创部分适用 ARL-1.0(弱传染,文件级互惠)**:核心文件(`ARL-CORE` 标记 / `crates/core/`、`crates/schema/` 目录)被修改后分发必须以源码形式回传开源;插件、壳、商业应用可闭源;允许商用;含专利授权与专利报复终止条款、30/60 日违约恢复条款、商业双许可保留。
2. **混合授权布局**:`LICENSE`(ARL-1.0,原创部分)+ `LICENSE-OPENCUT.MIT`(上游原文逐字保留,派生/参考部分)+ `NOTICE.md`(归属与声明)。MIT 就冲突部分优先(ARL-1.0 第 4.4 条显式让位)。
3. **已发布版本不可撤回**:CutFlow 已发布 tag 的 MIT 授权永久有效,许可变更仅对新版本生效;NOTICE 显式写明。
4. **三方工具不打包**:Ghostscript(AGPL v3)、poppler(GPL v2)、WPI(无许可声明)一律不进任何分发产物,仅作为用户本机可选外部依赖(沿用 CutFlow 的 `config.artboard_dir` 做法)。
5. **发布前置**:协议文本发布前必须经执业律师复核;本 ADR 与计划书附录 A 均不构成法律意见。

## 后果

- 正面:核心开源回传与商业生态兼得;与 MIT 派生部分合法并存;名称/商标边界清晰(ARL 第 6 条)。
- 代价:自定义协议的解读成本高于标准协议;门禁需检查三件套齐备与关键词;诉诸执行时的司法不确定性(中文版为准条款 + 律师复核缓解)。
- 明确非目标:不追求与 GPL 作品合并分发;AGPL 场景(网络服务分发 wasm)在 ARL 3.3 有条件覆盖,但涉及 Ghostscript 的网络服务仍需单独评估。

## 替代方案

- **整仓 MIT**:否决——核心修改可闭源,编辑器内核被商业魔改后无法回传,放弃互惠保护。
- **AGPL-3.0**:否决——强传染吓退壳/插件/商业集成,与"插件优先、多端壳可闭源"的架构目标冲突;且网络服务条款会波及 wasm 分发场景的边界判断。
- **MPL-2.0 原文**:可行但放弃自定义条款(商业双许可保留、名称主张、中文版为准);若未来律师复核建议换标准协议,替换 LICENSE 即可,本 ADR 其余布局不变。
