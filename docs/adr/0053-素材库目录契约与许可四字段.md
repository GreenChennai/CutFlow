# ADR-0053: 素材库的目录契约与许可四字段

日期: 2026-09-26 - 状态: 已采纳(v0.20 已落地) - 来源: 《CutFlow-迭代计划-v2-20260925》主册 §3(转写自桌面蓝本,以蓝本为权威)

**状态**：已采纳(v0.20 已落地) · **关联**：v1 ADR-0051（风格包）、ADR-0007（命名）、artboard `fonts/` 机制

#### 背景

现状（分册03 已核）：**音效只有 7 个 mp3**（`assets/sfx/`），且规则表承诺的「强调→ding」「列举→click/pop」**代码从未产出**（`ding`/`pop` 闲置）；**无元素贴图库**；**无花字**；BGM 有 4 条自产；**字体硬编码 `Microsoft YaHei`，仓库内 0 个 `.ttf`**，跨机器必不一致。许可侧只有 `assets/sfx/CREDITS.md`，**无机器可读的许可字段**。

用户明确：**字体不另建，链接 artboard 的 `fonts/`**（本技能已与 artboard 绑定）。

#### 决策

1. **四类素材库**（字体除外，见第 4 条）：

```
skills/cutflow/assets/
├── sfx/            音效        (现有 7 个 → 扩充)
├── elements/       元素贴图    (新增)
├── huazi/          花字模板    (新增)
├── bgm/            背景音乐    (现有 4 条自产 → 扩充)
└── manifest.json   ★ 四类统一索引（机器可读）
```

2. **每一条素材必须登记四个许可字段**（硬约束，缺一即 gate 失败）：

```json
{"id": "sfx.whoosh.01", "kind": "sfx", "file": "sfx/whoosh_01.mp3",
 "tags": ["转场", "冲击"], "mood": "energetic", "durationMs": 620,
 "gainHintDb": -12,
 "source": "Mixkit", "license": "Mixkit Free License",
 "commercial": true, "attribution": "Mixkit (mixkit.co/free-sound-effects/)"}
```

- `source` 来源 / `license` 许可名 / `commercial` 可否商用 / `attribution` 归因文本；
- **`commercial: false` 的素材一律不得进入交付**（`rs_verify` L0 加判据）；
- 交付时自动生成 **`成品/说明书/素材归因.md`**（由 `manifest.json` 汇总，清掉「只有 CREDITS.md 手写」的旧做法）。

3. **素材来源白名单**（只允许三类）：**CC0 公共领域** / **自产合成**（如现有 4 条 BGM 与音效）/ **明确可商用授权**（如 Mixkit Free License）。白名单外的来源必须由用户显式放行并留痕。

4. **字体不新建系统**：`rs_subtitle` 与 artboard 卡片**统一查 artboard 的 `fonts/`**，通过 `config.artboard_dir` 解析；**不把 `.ttf` 放进 CutFlow 仓库**；缺失时按 v1 ADR-0049 的懒加载三态处理（下载或降级并留痕）。硬编码 `Microsoft YaHei` 改为**查表兜底**（表在 `templates/fonts.json`，由 artboard `fonts/README.md` 生成对拍）。

   **✅ artboard 路径已锁定**（用户 2026-09-26）：**以工作区级 `E:\平日资料\GitHub\.agents\skills\artboard` 为准**；用户级 `C:\Users\Velon\.codebuddy\skills\artboard` 的副本（14.51KB vs 15.95KB，内容不一致）**不作为准**。`config.artboard_dir` 写死该工作区级路径；`rs_doctor` 检出「配置路径与两份副本都不一致」时报错。

5. **素材不重导出**：与 artboard 节点一致——按内容 hash 判断，没改的不重算。

#### 取舍

- 付出：素材的维护与许可核对成本；`manifest.json` 需长期维护。
- 换来：Agent 剪辑时**有素材可用且知道能不能商用**；交付自带归因清单（规避版权风险）；字体一致性问题从根上消失。

#### 被否决的替代

- **把素材塞进 `templates/`**：否决——`templates/` 是契约与配置，素材是二进制资产，混放会污染缓存键与对拍。
- **不做许可字段，沿用 `CREDITS.md` 手写**：否决——手写会漂移，且无法机械校验「不可商用素材流入交付」。
- **CutFlow 自建字体系统**：否决——用户已明确链接 artboard；两套字体源必然不一致。

#### 四问

| 问 | 答 |
|---|---|
| **旧工程怎么办** | 旧工程只引 `assets_sfx:<name>` 伪协议，**name 不变即行为不变**；`manifest.json` 缺失时按现有 7 个音效的硬编码表兜底 + WARN `ASSET_MANIFEST_MISSING`。 |
| **门禁怎么把守** | ①`tests/test_assets.py`：`manifest.json` 每条必备四许可字段；`file` 真实存在；`commercial: false` 不得被任何风格包/提示词模板引用；②`rs_verify` L0 新判据「交付无不可商用素材」；③归因清单与实际引用一致（双向对拍）。 |
| **怎么验收** | 文案→出片全链，交付里出现 `素材归因.md` 且条目与 `manifest.json` 引用完全一致；故意放一条 `commercial:false` → L0 必须红。 |
| **怎么回滚** | 素材为独立目录 + `manifest.json`；回滚即还原目录与清单；旧硬编码兜底表保留（不删）。 |
