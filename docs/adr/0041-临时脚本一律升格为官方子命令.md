# ADR-0041: 临时脚本一律升格为官方子命令,Agent 禁止现写剪辑逻辑

日期: 2026-09-20 · 状态: 已采纳(2026-09-20 迭代落地) · 关联: ADR-0020(字幕词边界与 Agent 复核)、ADR-0034(schema 契约)、ADR-0040(意图编译器与能力目录)

## 背景

一次迭代中 Agent 为完成任务现写了三个临时脚本(`_drop_ghost_chars` / `_gen_cards` / `_apply_overlay`)。这类"现写"正是既有事故的成因:手改 wordline 曾动坏 `chars[].i` 契约(P3 教训)。"给定输入必得同一输出"的逻辑一旦散落在一次性脚本里,就不可测、不可复用、不可入能力目录,还会被下一个 Agent 重写一遍、重踩一遍坑。

## 决策

1. **任何"给定输入必得同一输出"的逻辑,必须进官方脚本、作为子命令实现,并登记进能力目录**;SKILL 硬规则:Agent 禁止现写剪辑逻辑,确需新逻辑时先升格再使用。
2. 升格形态统一为"官方脚本 + 显式子命令":行为入 argparse(可被手册命令对拍门禁机械验收),条目入能力目录(Agent 只读目录、不读源码)。
3. 临时脚本的生命周期只有两态:**要么当场用完即弃(不产出可复用价值),要么升格为官方子命令**;不存在"归档备用"的中间态。

## 取舍

- 付出:官方脚本与能力目录的维护成本上升(每个子命令都要进对拍门禁与能力目录)。
- 换来:逻辑稳定可测(进 pytest 基线)、行为可发现(Agent 查能力目录即知)、不再重复踩坑、省 token。

## 被否决的替代

- **允许"一次性脚本 + 事后归档"**:否决——归档即失忆,下个任务仍会重写;P3 教训证明现写脚本会在契约边界上出事。
- **只靠 code review 约束**:否决——Agent 流程里没有稳定的人工 review 关口,必须靠门禁与目录机械约束。

## 后果

- 新增剪辑语义的默认路径变为:设计子命令 → 进官方脚本 → 进能力目录 → 进手册 → 对拍门禁全绿。
- 能力目录随之扩容;Agent 的可调用面收敛为目录内条目,越界即视为违规。

## 落地证据

- `skills/cutflow/scripts/rs_align.py` 官方子命令集:`remap` / `retext` / `smooth` / **`prune-ghost`**(P28,幽灵字/幽灵句清理,本决策第一个样板)/ **`refresh-durations`**(P26,只重测时长不改文本);argparse `choices` 收口,越界子命令直接被拒。
- 能力目录登记:`skills/cutflow/capabilities.json` 含 `rs_align.py prune-ghost` 等条目;`rs_caps.py check` 做目录↔实现零漂移校验。
- 机械门禁:`tests/check_manual_cmds.py`(AST 重放 argparse 做解析级验收,绝不执行)+ `tests/test_v19_manual_gate.py`,手册里有、脚本没有的命令直接红。
- 测试基线:`tests/test_v17_break_tail.py` 覆盖 prune-ghost 行为。
