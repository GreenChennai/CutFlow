# ADR-0047: 可插拔能力注册表 —— 在不违反 ADR-0018 的前提下做引擎级实现

日期: 2026-09-25 · 状态: 已采纳（待落地） · 关联: ADR-0018（细化）、ADR-0040（风格注册表）、ADR-0013（阶段缓存）

## 背景

ADR-0018 定「videoType 是一级路由，**刻意不进代码分支**」。这条约束防止了分支爆炸，但当新类型带来**新算法需求**时，出现了机制真空（§1.3）：没有地方安放「节拍检测」「镜头切分」这类能力。

**关键洞察**：ADR-0018 禁止的是 **`if videoType == "混剪": ...` 这种按类型硬编码**，**不是**禁止引擎级能力。真正的解法是**两级解耦**：

```
videoType（数据）──声明──► 需要哪些能力（数据）
                              │
                     能力注册表（数据）──挂载──► 阶段（引擎的通用机制）
```

引擎只认识「阶段」与「能力」，**永远不认识 videoType**。

## 决策

1. **能力描述符（Capability Descriptor）**：新增 `templates/capabilities/*.json`，每条声明：

```json
{
  "id": "beat-sync",
  "label": "节拍卡点",
  "appliesTo": ["混剪", "vlog"],
  "stage": "S2",
  "detector": "rs_beat.py",
  "depends": ["audio.beat", "audio.downbeat"],
  "degrade": {
    "to": "onset-energy",
    "trace": "beatDegraded",
    "message": "未部署节拍模型，已降级为能量起音；卡点精度下降"
  },
  "params": {"snapWindowMs": 60, "minGapMs": 400},
  "artifact": "04_粗剪决策/beats.json",
  "verify": "tests/test_beat.py"
}
```

2. **`registry.json` 的 `videoTypes.<id>` 增加 `capabilities: [...]` 字段**；`rs_intent compile` 据此在 `resolved` 里产出 `capabilities` 列表（与现有 `resolved` 字段同构，继续留痕于 `decision_log`）。
3. **`rs_run.spec()` 从「写死的阶段表」改为「阶段表 + 能力挂载」**：阶段注册表保留（它是管线骨架），但每阶段的**额外步骤**由能力描述符声明，由通用挂载器挂上。
4. **引擎侧断言**：`rs_run` / `rs_render` / `rs_cut` / `rs_ir` 中**不得出现 videoType 字符串比较**。加门禁测试把守。

## 取舍

- 付出：多一层间接（能力 → 阶段）；能力描述符需要维护。
- 换来：新类型 = 加 `videoTypes` 条目 + 加能力描述符 + 加一册分册，**真正不改引擎**；能力可跨类型复用（`beat-sync` 同时服务混剪与 vlog）；缺失可降级且有留痕。

## 被否决的替代

- **允许 `if videoType ==` 分支**：否决——直接违反 ADR-0018，且类型数一多必然失控。
- **给每个类型写一个独立 `rs_<type>.py`**：否决——8 个类型 = 8 套平行管线，复用面归零，回归成本爆炸。
- **把能力做成 Python 插件（动态 import）**：否决——不可机械审计、进不了 argparse 对拍门禁，与 ADR-0041 冲突。

## 影响

- `templates/capabilities/` 新增；`registry.json` 扩字段；`rs_intent` 产出 `capabilities`；**registry 键真实性测试扩展**（`test_v21_prompt_auto.py` L89–113 已在做）。
- ⚠ **命名风险**：`capabilities.json`（能力目录：Agent 可调用的脚本／命令清单）与 `templates/capabilities/`（能力描述符：引擎的算法能力声明）**名字相近但不同物**。文档与 `SKILL.md` 必须显式区分（见 §9）。

## 四问

| 问 | 答 |
|---|---|
| 旧工程 | 能力列表缺失时，`rs_run` 按 `registry` 兜底 + WARN `capabilitiesMissing`，旧工程行为不变。 |
| 门禁 | ①`tests/test_capabilities.py`：每个描述符的 `detector` / `artifact` / `verify` 真实存在，`appliesTo` 的键真实存在于 `videoTypes`，`stage` 在 S0–S11 内；②**引擎无 videoType 分支**扫描。 |
| 验收 | 新增一个类型（如 `interview`）**只加 3 处数据**（registry 条目／能力描述符／分册）即可跑通对应阶段，`rs_run.py` **零改动**。 |
| 回滚 | 描述符为独立文件；回滚即删除并还原 `registry.json` 的 `capabilities` 字段。 |
