# ADR-0023:亚帧转场提升 + 尾帧扩展交叉溶解(时间零漂移)

状态:已采纳 ｜ 日期:2026-09-14(v0.10,用户反馈#2)

## 背景

店群工程段间切换时人物"瞬间消失再显示"。根因:v0.8.2 B2 的保守规则——转场 `durMs < 1帧` 时**整链弃用转场**,退回 `-c copy` 无损硬切。粗剪常产出 8ms 量级的转场字段(意图是"柔一点",不是硬切),于是所有跳切都是硬切:人物位置瞬移 + 抠像 alpha 单帧跳变,读感为"闪烁"。直接放大 durMs 又不可行:xfade 要求两输入有重叠段,重叠只能来自**被剪掉的源间隙**,间隙放不下重叠时 xfade 会坍缩(这正是 B2 当初弃用的原因)。

## 决策

1. **亚帧转场提升**:转场 `type` 非 cut/none 且 `0 < durMs < 1帧` 时,自动提升为 `joinCrossfadeMs` 交叉溶解(默认 120ms;doc 级 `joinCrossfadeMs` 或 `config.render.joinCrossfadeMs` 可覆;设 0 禁用提升,恢复 B2 行为)。意图(柔化衔接)被保留,而非按字面 8ms 坍缩。
2. **尾帧扩展法保时间模型**:`step_segment` 渲染段 i 时多取 `tails[i]`(= 段 i 与 i+1 的转场时长)秒的源尾帧入段文件;`step_concat` 的 xfade `offset` 恒等于**后段名义起点** `sum(qdurs[:i])`(qdurs = 帧量化后的名义时长)。于是 xfade 重叠完全落在前段多出的尾帧里,成片时间轴与 IR/字幕时间**零漂移**;末尾 `-t total_s` 裁齐,尾帧只进重叠不外溢。
3. **帧量化段边界**:`sourceInMs`/`durationMs` 吸附到帧网格(`q_in_ms`/`q_out_ms`),消除半帧散差在 xfade offset 上的累积。
4. **保守回退保留**:仅当某衔接点**源间隙放不下尾帧扩展**(`gap_ms < tdur×1000`)才整链弃用转场走 concat(宁硬切勿错位);`type=cut/none` 仍是显式硬切。`tailMs` 纳入段缓存键——尾帧计划变化必须换键重渲。
5. `CACHE_VER` v2→v3:转场语义变更,旧 segcache 必须整体失效。

## 后果

- 亚帧转场读感从"硬切闪烁"变为平滑溶解;成片时长/字幕时间与 IR 严格一致(rs_sync 对账不受影响);
- 每段多渲 `tails[i]` 秒源帧,渲染量小幅增加(段内,无重编码放大);
- "整链一致"约束仍在:一处放不下 → 全链 concat。多段工程若仅个别间隙紧张,会损失其它点的溶解——刻意保守,未来可做逐点回退(per-join cut)但当前不值得复杂化;
- 字幕若在溶解窗内换卡,溶解期间两段画面半透明叠加属预期效果。

## 关联

- `rs_render.py`:`_resolve_transitions()`、`step_segment()`(tailMs/帧量化/take_s)、`step_concat()`(xfade offset/`-t` 裁齐)
- 取代 B2 规则的"tdur<1帧整链弃用"分支(其 `-c copy` 回退仅剩源间隙不足一路)
- `tests/test_v10.py`:提升/回退/offset 对账断言
