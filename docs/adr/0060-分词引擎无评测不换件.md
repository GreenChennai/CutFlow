# ADR-0060: 分词引擎抽象可插拔,但"无评测不换件"——保留 jieba 为默认

日期: 2026-09-27 - 状态: 已采纳(第四册 T4.8/T4.9 落地) - 来源: 《CutFlow-多册迭代计划》第四册 B 组(BACKLOG v0.8.2 分词主诉)

**状态**：已采纳 · **关联**：ADR-0020（词边界与两阶段 DP）、`templates/subtitle-policy.json`（T4.4 策略表）、`tests/fixtures/segboundary_gold.json`（T4.9 金标）

#### 背景

第四册要求把分词从「jieba + 兜底词表」升级为**可切换、可评测、可回归**的引擎（T4.8），并建立 300–500 条领域内金标（T4.9）。换引擎的唯一合法理由是**评测结论**，而不是「新引擎看起来更强」——即计划文档的工程纪律：**无评测不换件**。

#### 决策

1. **引擎抽象落地**（`segmentation.py`）：`Tokenizer` 接口 + 五实现 `jieba / pkuseg / lac / hanlp / lexicon`（兜底词表）；懒加载三态（unchecked→ready/missing），缺失即降级并把「降级到 X」写进留痕；`config.json` 的 `subtitleTokenizer` 字段可选指定，缺省 `auto`（jieba→lexicon 链）。
2. **金标与 F1 口径**：`tests/fixtures/segboundary_gold.json` 现为 **358 条**领域内（口播/电商/财税/教程）「允许切点」金标（含 P30-5 全部已知案例与 rules/subtitles.md §4.7 全部用例的词界）。F1 在「允许切点集合」上计算：引擎把词切开（不该切却给切点）伤召回、把两个词并成一个跨度（该切不给切点）伤精度。
3. **换件判据**：候选引擎 F1 ≥ 现引擎 +0.03 才换；否则**保留现引擎**并把结论记进本 ADR。
4. **2026-09-27 评测结论**（358 条金标，逐条 F1 平均）：

   | 引擎 | 本机状态 | 边界 F1 |
   |---|---|---|
   | jieba（现默认） | 可用 | **0.876** |
   | pkuseg / LAC / hanlp | 未安装（降级到 jieba，留痕生效） | = jieba（降级路径） |
   | lexicon 兜底词表 | 可用 | 0.735 |

   **结论：保留 jieba。** 无任何可用替代引擎达到「+0.03」门槛（pkuseg/LAC/hanlp 均未部署；为测试注入的假实现只用于打通驱动与降级路径，不是真实候选）。待真实部署任一引擎后，重跑 `tests/test_segboundary_gold.py` 的 F1 评测再决策。
5. **防退化**：金标 F1 成为回归基线——`test_segboundary_gold` 断言 jieba F1 ≥ 0.75（0.876 − 0.12 容差，防词表/打分改动悄悄掉分）；引擎切换必须同时提交新的评测数字与本 ADR 的增补记录。

#### 后果

- 换引擎从此是一条**有据可查的流程**（金标 → F1 → 本 ADR 增补），不是随手改一行；
- jieba 保持**可选依赖**地位：未安装时降级 lexicon（F1 0.735 仍可用），由 rs_doctor 报告状态；
- 金标由 `tests/fixtures/make_segboundary_gold.py` 确定性生成，新增领域案例 = 补题库 + 重生成，条目可审计。
