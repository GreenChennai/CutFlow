# ADR-0028:ASR 热词链路(默认模型即 SeACo,透传即生效)

状态:已采纳 ｜ 日期:2026-09-14(v0.12,I1;含 2026-09-14 本机实测结论)

## 背景

onnx 降级后端下专有名词全错(投喂→位、SEO→ICO、新闻源→西闻源),复盘已写明"字幕/对齐用途必须 pkg 后端"。但 pkg 后端下专名仍需热词:`tools/fun_asr.py` 已有 `--hotwords` 且 CAPS 声明支持,`rs_align.py` 却完全不透传——链路断在中间。

交接文档留了一个**待验证事实**:热词增强是 SeACo-Paraformer 的能力,而默认模型 `paraformer-large` 经 `HUB_ALIAS` 映到 `paraformer-zh`——默认模型到底吃不吃热词?若不吃需给 config 增 SeACo 档。

## 决策与实测结论

**实测(2026-09-14,本机 venv)**:`funasr` 包内 `download/name_maps_from_hub.py` 明确
`"paraformer-zh": "iic/speech_seaco_paraformer_large_asr_nat-zh-cn-16k-common-vocab8404-pytorch"`,
且 `funasr/models/seaco_paraformer/model.py` 注册注释 "Registered as 'paraformer-zh' alias"。

**结论:默认模型 `paraformer-zh` 就是 SeACo-Paraformer,热词是其模型级原生能力,透传即生效,无需新增模型档。**(官方热词样本 `asr_example_hotword.wav` 开/关对比文本一致——该样本全是常见词,无法证伪;以源码映射为准。)

链路补全(最小改动):

- `rs_align.py build` 新增 `--hotwords "词1 词2"` 与 `--terms-file <txt|json>`(每行一词,`#` 注释;约定落 `00_brief/terms.txt`,来源 brief.md 术语表),合并去重后透传 `fun_asr.py --hotwords`;
- wordline 顶层 `asr.hotwords` 留痕(复跑/排障要知道当时喂了什么);
- 规则:`rules/asr.md` §5.1——**专名错 → 先补热词重跑,不要手工改字**(手改经 retext 固化错误时间锚);onnx 后端不支持(capabilities.hotwords=false)。

## 影响

- 专有名词识别质量不再依赖"整段重跑+人工校对"的最贵路径;
- 无新模型、无新依赖(零成本,符合克制原则);I4 说话人分离维持 P2 不做(见 BACKLOG);
- 若未来切换默认模型(离开 SeACo 家族),热词能力需重新实测——本 ADR 的实测依据随之失效。

## 回滚

参数为纯透传,不传即旧行为;`asr.hotwords` 字段仅留痕,无消费方依赖。
