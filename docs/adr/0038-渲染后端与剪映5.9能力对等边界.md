# ADR-0038: 渲染后端与剪映 5.9 的能力对等边界

日期: 2026-09-17 · 状态: 已采纳 · 关联: ADR-0037(N 后端注册表)、ADR-0027(纯动画)、`references/ffmpeg-recipes.md`

## 背景

CutFlow 的"可继续精修"退路依赖剪映 5.9 明文草稿(6.0+/11.3 已加密,永不读写;剪映属第三方商业软件且可能强制用户升级)。CutForge 作为第三后端,必须明确"做到什么程度才算取代这条退路"——否则用户不敢弃用剪映精修,退路悬空。

## 决策

1. **能力对等矩阵是 M6 的判定物**:以剪映 5.9 的 15 项能力(裁剪排序、变速 0.25–4x、音量/淡入淡出、位置缩放、转场三级语法、关键词、花字描边底衬、音效落点、BGM ducking、蒙版、冻结帧、punch-in、ASS 字幕烧录、多画幅变体、工程可继续精修)逐项标注三个后端的支持情况,存档 `docs/capability-matrix.md`。"必达"项全部达成且整体达成率 ≥ 90% 才算通过。
2. **七步管线顺序不可绕过**:cutforge-render 必须复刻 rs_render 的语义顺序——统一帧率 → 逐段提取 → concat → 合成 → 混音 → **字幕最后叠** → 编码;字幕用现有 subtitles.ass,绝不重新生成(S8 护栏)。
3. **既有配方照抄**:`-t` 输入侧、loudnorm 双 pass linear(I=-14/TP=-1.0,人声预归一 I=-16/TP=-1.5)、BGM ducking 的 amix→asplit 侧链、ASS 滤镜盘符转义(cwd+相对路径)、段间 8ms afade、HDR→SDR zscale 链——违反会静默出错,一律照抄不得"优化"。
4. **缓存键算法与 Python 侧同源**:段级缓存键含渲染器语义版本,行为变更必须导致缓存失效;对拍(时长差 ≤1 帧、响度差 ≤0.5 LU)失败必须查明根因,不得放宽阈值。
5. **剪映退路不删除**:`jianying` 后端保留(可生成 5.9 明文草稿);cutforge 是"新增第三后端",不是"取代既有后端";工程导出(可继续精修)是 cutforge 的必达项,这是取代剪映的关键。

## 后果

- 正面:CutForge 何时可以接管精修有了可门禁的判定;两个渲染后端的对拍一致成为防双实现漂移的硬闸。
- 代价:实现顺序被管线语义锁死,不能按 Rust 侧方便随意重排;FFmpeg 版本差异可能造成对拍抖动(对拍前固定并记录 ffmpeg 版本)。
- 边界:关键词/蒙版属"可选"档,未达成不阻断,但必须在矩阵中如实标注;自动抠像/背景合成仍归用户(ADR-0031),任何后端都不得扩张。

## 替代方案

- **只对拍时长不对拍响度**:否决——音频静默劣化(响度漂移)正是"看起来成功"的半成品,必须双指标 + QC 体检 + 对齐断言四闸。
- **cutforge 直接用自有渲染器替代 FFmpeg**:否决——与 CutFlow 既有七步管线口径一致是可对拍的前提;自研渲染器是远期选项,当前拒绝。
