## 3. P0 详单

### #1 rs_render seg 级缓存 + 单卡重渲（v4-B3/B4/B5）

- **问题**：`rs_render` 只有整条时间线渲染（`--profile final|preview|draft`，crf 19/26/28 三档），没有任何 seg 级缓存（grep 证实）。改一个字、换一张卡、调一个字幕样式，都要全片重渲，一次迭代几分钟起步；管线其他阶段都有内容寻址缓存，唯独渲染这个最贵的环节没有。
- **方案**：
  1. 渲染拆为**分段渲染 + 拼装**两步：每卡（或每连续段）先出独立分段文件，再用 concat demuxer 合成整片；
  2. 缓存键 = hash(seg 内容指纹 + 该卡字幕 + profile 参数 + 关键 ffmpeg 参数)，落 `cache/render/<profile>/`，沿用 stage manifest 的内容寻址思路；
  3. `--profile` 三档参数作为 hash 输入，档位间不串缓存；
  4. `rs_render --explain` 逐段显示 命中/重渲 与原因；`--clear-cache` 清理。
- **验收**：同一工程二次渲染零改动命中 ≤2s；只改第 N 卡字幕 → 仅该卡重渲，端到端 ≤10s（1080p 预览档、10min 工程参考）；成片与整片直渲抽 5 帧对比，音画无漂移、无黑帧/跳帧。
- **成本**：1–2 人日。**风险**：分段拼装的 A/V 连续性是主要风险，见 §7。

### #2 校对回灌 `rs_align retext`

- **问题**：人工校对逐字稿后，wordline / DP 分段 / CutList 全都不会跟着变——`rs_sync` 报告里只出现"校对未重聚合"一行提示，没有任何工具承接。校对改得越多，下游字幕、切点、粗剪与真实语音偏差越大，且下次 `--from` 重跑还有被旧缓存"洗回去"的风险。
- **方案**：新子命令 `rs_align retext --take 01 --file transcript.01.proofread.txt`：
  1. 用 `difflib` 把校对文本对回原 dense 文本，把改动定位到**字级锚点区间**（pkg 后端 334↔334 锚点已就位）；
  2. 区间内字数变多 → 在锚点区间内做局部线性摊派；变少 → 删除对应锚点。与"禁止比例插值"禁区不冲突：禁区针对**无锚点的整段缩放**，retext 是锚点兜底的区间内插值，此边界写进 `rules/align.md`；
  3. 重跑 DP 分段 → 更新 wordline（版本号 +1，provenance 记 `retext`）；
  4. 时长守卫：重聚合后时长偏移超阈值（建议 ±15%）的卡标 `needs_review`，不静默通过。
- **验收**：实测样本上改一个词（如"耐心"→"勇气"）、增删一个短句，重聚合后时间戳单调、无负区间；下游 S4 重跑 diff 只落在受影响卡；守卫对超阈值卡正确标黄。
- **成本**：1–1.5 人日。

### #3 卡拉OK 逐字字幕（激活 BACKLOG IDEA 项）

- **问题/机会**：BACKLOG 原条目"卡拉OK 式逐字字幕（需字级时间戳，当前 FunASR 只有句级）"——前提已不成立：pkg 后端实测 334 字↔334 条时间戳。`rules/align.md` 与新闻采访模板也都把它列为未来可能，现在只差渲染出口。
- **方案**：
  1. `rs_subtitle --style karaoke`（或 config `subtitle.karaoke: true`）：ASS `\k` 标签按字级 timestamp 生成逐字染色，行切分沿用 DP 分段结果；
  2. 强约束：karaoke 行**只允许 pkg 后端**（onnx/server 无时间戳时拒绝并给出明确提示，避免静默插值回禁区）；
  3. 降级路径：非逐字环境自动回落普通行级字幕，manifest 记 `karaoke: degraded`。
- **验收**：实测样本生成 karaoke ASS，ffprobe 可解析、ffmpeg 烧录无报错；抽查 3 行首/尾字染色时刻与 timestamp 误差 ≤50ms。
- **成本**：0.5–1 人日。

## 4. P1 详单

### #4 lavfi 合成视频集成测试

- **问题**：A3/A4/A5、C5、D5、D6、E5 这批验收项全部卡在"需真实素材"，永远无法自动化回归；目前 68 个测试全是单元级，S0–S11 端到端没有任何断言。
- **方案**：`tests/make_fixture.py` 用 ffmpeg lavfi 合成 30–60s 测试片（testsrc + 已知时刻的场景切换 + sine 音轨 + 已知文本叠加），配一份人工核过的期望（切点位置/卡数/CPS 区间）；集成测试跑全链路断言关键产物。真实素材验收（A4 retake 检出等）仍需真人素材，但切点一致性、CPS、字幕合规这类机械指标可先用合成片锁住回归。
- **验收**：合成片全链路跑通且断言全绿；人为在 fixture 里埋一个坏切点能被抓到。
- **成本**：1 人日。

### #5 GitHub Actions CI

- **问题**：仓库目前没有任何 CI（`.github/workflows` 为空），68 个测试只在本机跑。
- **方案**：单 workflow：ruff + pytest（ubuntu + 预装 ffmpeg；ASR 相关单测 mock，不下载模型）；打 tag 时跑。可选加 pytest 随机顺序防隐性依赖。
- **验收**：push/PR 全绿；本地故意注入一个失败能被 CI 拦住。
- **成本**：0.5 人日。与 #4 组合收益最大。

### #6 烧录字幕 OCR 回验（rs_verify L1.5）

- **问题**：L1 只出"清单与抽帧命令"，烧录后字幕是否真的渲染正确（字体缺失、样式错乱、越界截断）全靠人眼。
- **方案**：`rs_verify --ocr-check`：成片每卡抽 1–2 帧 → 调本机 OCR.exe（RapidOCR 离线，路径进 config 可选项）→ 与该卡期望字幕做相似度比对（建议阈值 0.85），输出差异清单。OCR.exe 缺失时跳过并提示，不阻塞。
- **验收**：实测样本 OCR 回验全过；人为在 ASS 注入错字/丢行能被抓住。
- **成本**：0.5–1 人日。

### #7 cam++ 说话人分离

- **机会**：本机已有 cam++ 说话人模型（MomentShift `tools/funasr/` 下）；访谈、双人播客类素材目前切卡/粗剪完全不感知说话人。
- **方案**：`fun_asr.py --diarize`：cam++ 提取说话人嵌入 + 聚类，输出 `[12.3s] 说话人0:` 结构化分段；rs_asr 分段携带 speaker 标签；CutList 可按说话人过滤/保留。**先做 0.5 天可行性探测**：cam++ 本机是 ONNX 权重，pkg(torch) 链路可能需要另下 torch 版，探测后再排期。
- **验收**：双人样本说话人标签人眼抽验正确率 ≥90%；不开启时行为与现状完全一致。
- **成本**：1 人日（含探测）。

### #8 TTS 配音强制对齐（配音闭环第一砖）

- **机会**：pkg ASR 本质是一台免费的对齐器。TTS（EchoSmith）生成配音后，用 pkg 转写拿字级时间戳，与 wordline 期望文本对齐，即可得到每卡配音的实际起止与偏移。
- **方案**：新工具 `rs_dub align`（先只做对齐报告，不做自动变速）：输入 TTS 音频 + wordline → 输出每卡实际时长、偏移、超阈值卡清单与建议（改稿/变速率）。顺带覆盖 v4-P2 的"fa-zh 强制对齐偏移自检"同类需求。
- **验收**：3 卡 TTS 音频实测，报告偏移与人手测一致（±0.2s）。
- **成本**：1 人日。

### #9 补 `rs_ingest`(S0) + deliverables.md 生成

- **问题**：v4/v5 已知待办里挂了两轮的 P1：S0 素材摄取（重命名、probe 元数据、生成 IR 骨架）仍靠手工；交付清单（成片路径、校验状态、章节时间戳）也没有自动汇总。
- **方案**：`rs_ingest` 承接 raw → `01_footage/`（probe 出时长/分辨率/帧率写 manifest）；`rs_run` 尾部自动生成 `deliverables.md`（复用 rs_meta 的章节时间戳）。
- **验收**：丢入新素材一条命令完成摄取；跑完管线自动产出交付清单。
- **成本**：0.5–1 人日。

## 5. P2 详单

### #10 conf 真实化（token 级置信）
分段置信度目前偏"整段一个数"，段内个别字的低置信被均值掩盖。方案：pkg 路径探测 funasr 是否暴露 token 级 confidence，拿到后把分段 conf 改为 `min(字置信)`，模糊卡判定接入。0.5 人日（先 0.25 天探测再定）。

### #11 fun_asr re-exec 后台健壮性
`maybe_reexec()` 的 `os.execv` 在 Windows 后台/重定向场景会丢输出句柄（2026-09-11 实测踩坑，只能手动改用 venv python 绕过）。方案：检测 stdout 非 tty 或环境变量 `CUTFLOW_BG=1` 时跳过 re-exec，同进程完成引导。0.5 人日。

### #12 rs_asr.py 旧转写器归并
`rs_asr.py` 仍是旧 HTTP-server 转写器（urllib 直连 MomentShift 服务），与 `fun_asr.py` 三后端链职责重叠，容易误导使用者。方案：改为薄封装（`backend=server` 时委托 fun_asr.py）或标记 deprecated 一个版本后删除；README 命令表同步。0.25 人日。

## 7. 风险与边界

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| seg 拼装 A/V 连续性 | 分段渲染 + concat 可能引入关键帧缝隙、音频爆点 | 验收含抽帧对比；不行则退"单文件 + 逐段章节时间戳"方案 |
| retext 与"禁止比例插值"禁区打架 | 边界模糊会导致实现走样 | 文档明确：禁区针对无锚点整段缩放；retext 是字级锚点区间内插值 |
| karaoke 静默降级成插值 | onnx 环境跑 karaoke 会退回按字数插值 | 强约束只允许 pkg，否则报错；降级路径必须记 manifest |
| cam++ / token conf 可行性未知 | 模型格式、funasr 暴露程度未探测 | 两项都先 0.5 天探测，探测不过不排期 |
| CI 上模型下载 | Actions 里下 944MB 模型又慢又抖 | 单测全 mock，集成测试用 fixture，不下载模型 |
