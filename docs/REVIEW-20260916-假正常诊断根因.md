# 源码专项审查:为什么诊断会得出"视频完全正常"的假结论

日期: 2026-09-16 · 审查范围: rs_verify.py / rs_sync.py / rs_run.py / rules/verify.md · 分支: feat/v0.13-alignment-chroma

## 用户的原始遭遇

用户发现成片存在「字幕和声音对不上 / 口型对不上 / 错剪产生无意义片段」等问题,
把视频交给 Agent 探查,Agent 花一两个小时后回复"视频很正常,完全没问题"——
但视频确实有问题。本报告回答:**这套代码为什么会产出这种假正常结论**。

## 根因链(五环,环环都有代码位置)

### 根因 1:所有机器闸都是「对照中间产物」的闸,不是「对照成片实际内容」的闸

CutFlow 的 L0 自检(`rs_verify.py` L0_CHECKS,skills/cutflow/scripts/rs_verify.py:275)
七项检查里,六项核对的是**工程自己生成的中间产物之间的一致性**:

| L0 检查项 | 实际对账对象 | 能发现用户说的三类问题吗 |
|---|---|---|
| IR 可解析(rs_verify.py:125) | project.json 自洽性 | 不能 |
| Wordline 单调(rs_verify.py:138) | wordline.json 自洽性 | 不能 |
| 粗剪 guard(rs_verify.py:165) | cutlist 决策表自洽性 | 不能——guard 只验证"刀切在静音区",不验证"剪完的内容还有意义" |
| 字幕合规(rs_verify.py:191) | ASS 自身字数/CPS/时长 | 不能——错位字幕的时间轴照样合规 |
| 字幕↔Wordline 对齐(rs_verify.py:223) | ASS ↔ wordline.json | **只能发现"字幕没按 wordline 渲染"**;如果 wordline 本身错了(ASR 偏移/粗剪重映射错),ass 与 wordline 依然完美一致——两个错的产物互相印证 |
| 产物存在(rs_verify.py:240) | mp4 文件存在 | 不能 |
| 成片体检 QC(rs_verify.py:247) | 成片视频流 | 只查黑帧/冻结/VFR/响度四种**物理**缺陷;字幕错位/口型错位/错剪语义全部不在检测范围 |

**结论**:用户问的是"成片的内容对不对",系统回答的是"管线产物之间自洽不自洽"。
当错误发生在**管线内部**(ASR 时间戳偏移、粗剪切错段、渲染音轨错位)时,
错误会同时传染给 wordline/ass/成片——所有对照闸拿到的是同一份错误的镜像,
互相印证,全部绿灯。

### 根因 2:仅有的两个「对照成片实际内容」的闸是 opt-in,默认不跑

`rs_sync.py` 有两个真正对成片内容跑检测的闸,但都是**命令行开关**:

- `--audio-content`(B10 音频内容闸,rs_sync.py:388):对成片音轨跑 ASR 与
  wordline 对账——这是唯一能发现"声音内容错了"的闸,但只在显式传参时运行;
  L0_CHECKS 里没有它。
- `--qc`(rs_sync.py:171):黑帧/冻结/VFR/响度,同样 opt-in(v0.12 起进了 L0,
  但只覆盖物理缺陷)。

且 B10 闸自身有三个盲区(rs_sync.py:430-455):
1. **相似度对账是文本级的**:`difflib.SequenceMatcher` 对"归一化全文"算 ratio——
   把视频后半段的音频错位 3 秒,文本内容一字不差,sim=1.0,照样通过;
2. **无时间轴对账**:ASR segments 的 start/end 与 wordline 的时间戳从未比对——
   "每个字都在,但出现的时间全错"是检测盲区;
3. **重复检测阈值粗**(≥3 次 × 20 字),只防极端事故。

### 根因 3:抽样过疏,人的眼睛被当成了"最后一道闸"

`rs_bench.py`(自评抽帧,rs_bench.py:22):首 2s/尾 2s/剪点 ±1.5s/随机 3 点——
一个 3 分钟 15 个剪点的成片抽约 11 帧。**字幕错位 200ms 在抽帧图上完全不可见**
(抽帧本身不叠加字幕时间轴信息);错剪产生的"无意义 3 秒"如果恰好不在采样
邻域,也看不见。

L1 清单(rules/verify.md §4)把"转场无跳变、无音画错位可感知"列为**目测项**,
但没有给 Agent 任何机械辅助——Agent 拿到 11 帧拼图,自然看不出 200ms 级错位。

### 根因 4:Agent 的探查路径没有"独立证据源",只有管线自己的产物

用户说"Agent 调用各种工具探查一两小时后说没问题"。复盘典型路径:Agent 查看
verify_report.md(全绿)→ sync_report.md(对齐 30ms 全绿)→ audio_check.json
(若跑过,sim 0.98)→ 抽帧图(看不出错位)→ 结论"没问题"。

**每一条证据都来自管线自己**(根因 1/2/3),没有任何一条是"从成片重新独立测量"
的:没有对成片音轨独立跑 ASR 对时间轴,没有从视频帧独立定位口型/字幕事件,
没有逐剪点审计上下文连贯性。用错误产物自己的体检报告证明产物没错——循环论证。

### 根因 5:「通过」被表述成「没问题」,违反自家规范

rules/verify.md §7 反模式明确写着:"把 L0 的通过说成成片没问题——L0 只保证
机械正确性"。但 `rs_verify.py` 的输出 JSON(`VERIFY_OK`)与 verify_report.md 的
"判定:通过"没有任何字段提醒"L0 通过 ≠ 内容正确";Agent 读到 `VERIFY_OK`
自然把它当"没问题"转述给用户。**结论语义与证据等级脱钩,是假正常的最后一环。**

## 三类问题对应的检测缺口

| 用户症状 | 为什么现有链路全绿 | 缺的检测 |
|---|---|---|
| 字幕和声音对不上 | ass↔wordline 一致(同一错误源),音轨内容闸无时间轴对账(根因 2) | **成片音轨独立 ASR → 逐句时间轴比对**(用成片实测,不用工程产物) |
| 口型/声音对不上 | 渲染端无任何音画同步探针;QC 只查黑帧/冻结 | **音画同步探针**:对成片测「语音活动 vs 画面人物活动」的相关延迟;无法判定时显式标注"无法机械判定"而不是放行 |
| 错剪产生无意义片段 | 粗剪 guard 只验切点位置合法,不验内容;QC 只查冻结/黑帧 | **剪点上下文审计**:每个 remove 刀的前后 1.2s 文本/音频完整性检查 + 成片 ASR 文本与源稿 diff 定位"被剪出的语义断裂" |

## 修复方向(见 ADR-0032 设计)

1. 新建 `rs_diagnose.py`:从成片出发的**独立证据诊断**(不读工程中间产物做判据,
   只做对照)——成片音轨独立 ASR 逐句时间轴 ↔ 字幕 OCR/ASS 双通道、音画活动
   相关延迟、逐剪点上下文审计;全部结论带时间段+证据;
2. `rs_verify` 输出语义分级:L0 通过输出 `scope: mechanical`,禁止 Agent
   依据 L0 说"内容没问题";新增 `--content` 级别入口;
3. 诊断台账(`06_output/diagnosis/`):每次诊断的检查项/耗时/证据/结论全留痕;
4. 缺陷注入回归集:错位字幕/错位音轨/错剪注入 → 新流程必检出(检出率纳入测试)。
